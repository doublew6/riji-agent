# A-MEM 方法研究与 Riji 产品推导

研究范围：官方论文、论文列出的官方实现，以及项目现有的产品/架构边界。未访问生产数据、未安装依赖、未执行官方库。本文所有日记内容示例均为合成示例。网页访问日为 2026-09-21；论文使用 v11；源码链接指向 `main`，实现前需另行固定并审计确切版本。

## 1. 可直接借鉴的原始方法

A-MEM 将内容与时间、关键词、标签、语境描述、向量和关联保存为原子笔记。新增笔记先检索语义近邻，再由模型判断关联和是否调整既有笔记的语义属性；一条笔记可以跨多个关联集合。论文评估主要面向 LoCoMo/DialSim 对话问答，组织质量依赖基础模型。每日/每周调度、稳定主题身份、用户审批和三端交互不是论文定义的成品能力。[论文方法与局限](https://arxiv.org/html/2502.12110v11)

官方 README 展示自动生成或人工提供语义属性、检索、修改和删除接口，也建议定期检查生成结果。它可以作为方法验证起点，不能替代 Riji 自己的来源、授权和运行验收。[官方系统仓库](https://github.com/WujiangXu/A-mem-sys)

源码观察：`MemoryNote` 有 `evolution_history` 字段；`add_note` 调用局部演化，`process_memory` 更新邻居标签/语境；`consolidate_memories` 重新写检索记录。初始化尝试 reset collection，主要对象保存在进程内字典；所审阅更新路径没有构成 Riji 所需的事务审计与撤权机制。这里仅为静态阅读，未验证运行行为。[memory_system.py](https://github.com/WujiangXu/A-mem-sys/blob/main/agentic_memory/memory_system.py)

检索实现把内容、语境、关键词和标签拼接后生成向量。这提示语义属性变化也可能改变后续召回，因此派生属性需要版本与来源约束。[retrievers.py](https://github.com/WujiangXu/A-mem-sys/blob/main/agentic_memory/retrievers.py)

## 2. 对 Riji 的产品推导，不冒充 A-MEM 原生能力

### 2.1 组织模型

建议采用“有依据的记忆笔记 → 可解释关联 → 动态主题 → 周期回顾”的组织层。六大分类可以保留为可选筛选，不再充当固定容器；一条笔记可以属于多个主题。

| 对象 | 必须保留的产品语义 | 不应隐含的结论 |
| --- | --- | --- |
| 记忆笔记 | 本人事实、本人计划、实际反馈、引用材料、AI 观察分别标识；来源 ID/版本、记录日期及有证据时的事件日期 | 一段 AI 总结不等于独立的新证据 |
| 关联 | 两端笔记、关联类型、成立依据、来源范围、生成/复核状态 | 相似不等于因果；同主题不等于同一事件 |
| 主题 | 稳定 ID、名称/别名、覆盖范围、代表证据、成员及结构版本 | 主题不等于人格定论或永久画像 |
| 主题变化 | 新增、改名、合并、拆分、休眠、恢复的前后差异及依据 | 没有新记录不等于目标终止；休眠不等于删除 |
| 巩固/复盘 | 输入截止点、已覆盖及未覆盖来源、生成时间、可用结果版本 | 成功产出报告不等于处理完全部日记 |

### 2.2 三个处理时间尺度

建议日常新增只做必要的局部处理；每日、每周和结构维护使用同一条受控任务链，避免三个定时任务重复提取原文。

1. **增量处理**：已授权的新来源或来源变化进入队列；完成提取后建立局部关联；优先处理纠正、删除、撤权造成的失效。该失效传播不应等待夜间任务。
2. **每日巩固**：以有版本的输入清单处理当天新增、修改、纠正项及其有限邻居；合并展示重复、补充关联、更新主题摘要，产生“今天记忆发生了什么变化”。无新增且无待维护项时记录跳过原因，不调用模型硬写总结。
3. **每周复盘**：在已完成的有效笔记上比较一周变化，回答持续关注什么、计划有何反馈、哪些判断出现反例、哪些主题有结构调整建议。报告明确缺口，不补造缺失日记。
4. **长期结构维护**：先在每周复盘中识别结构问题，跨周期证据充分后提交主题合并/拆分/改名建议。采用稳定主题 ID、别名与重定向，避免用户入口频繁消失。更长周期的全量维护只能在授权与资源预算内分批推进。

**时间规则建议**：用户时区决定日/周边界，默认时间由主 PRD 明确；任务按周期与来源版本幂等。Air 休眠/离线后有界补跑，用一个补跑窗口整合欠账，不连续补发多份空报告。上个周期有缺口时允许先提供部分结果，后续补齐生成修订版并保留区别。记忆复盘默认保存为记忆产品产物；写入原周记/月记仍走已有预览确认，不自动改日记。

### 2.3 三端职责

| 端 | 核心职责 | 可见的可信状态 |
| --- | --- | --- |
| Air 后台 | 唯一调度与权威处理端；许可校验、局部组织、周期巩固、版本提交、失败恢复、预算账本、派生失效 | 实际排队/执行/成功/部分/等待额度/失败停止；明确下一次资格时间 |
| 网页 | 深度核对、主题整理、结构变更对比、来源追溯、批量复核和运行详情 | 当前有效组织版本、结构变更原因、影响的记忆和主题，失败原因与有界重试 |
| 手机 App | 短时浏览今日变化、每周回顾、主题进展；轻量纠正、复核和打开原日记 | Air 确认状态、缓存更新时间、离线更改待确认；不能把本机点击显示成远端已生效 |

两个人类界面消费同一主题、笔记、报告和处理状态契约。图谱可作网页探索辅助；手机默认主题卡片、时间线和依据抽屉，不要求用户阅读节点网络才能理解自己的记忆。

## 3. 抑制幻觉与结构漂移的必要约束

以下为 Riji 的产品/安全要求，不能用“采用 A-MEM”代替验证：

- **来源保真**：派生摘要、标签、关联与主题各自绑定输入 ID、版本与用途；模型不得覆盖原日记或既有本人纠正。
- **性质保真**：事实、计划、观察分别展示；观察不递归充当新的事实依据。不能因主题反复引用同一原文就增加支持证据数。
- **受限演化**：每次只允许有限邻居、有限修改量、限定关联深度；结果先校验再提交。失败保留上一有效版本，不发布半个主题结构。
- **用户控制**：本人改名/合并/拆分/纠正优先；可锁定名称或成员边界；系统下次整理不得悄悄撤销。自动生成新主题可直接出现并可撤销；对既有稳定结构的大改动以清晰差异供复核。
- **身份稳定**：主题 ID 不随名称改变；合并保留旧入口，拆分保留原主题的去向与历史；拒绝过的建议有原因/版本记录，不能每周原样骚扰。
- **语义克制**：明确的更新可以标记旧阶段失效；冲突证据并列呈现并待复核。单次情绪不升级为长期性格；因果关系必须有直接证据或明确标为待验证假设。
- **权限全链路**：关系与跨主题扩展每一跳都校验来源、用户、导师及用途；摘要不是权限绕行。来源删除/撤权时同时失效报告、关联、主题摘要、检索索引与缓存，不等待下一次周期。
- **资源与失败**：沿用既有单片段/来源版本/UTC 日预算及初始化例外范围，不把周期机制变成重新发送全部历史的许可；待额度和终止失败不能继续混称“整理中”。

## 4. 合成验收场景

### 场景 A：从零散记录形成可回看的主题

周一记录“计划每周跑步三次”；周三记录“跑了二十分钟”；周五记录“膝盖不适，暂时改为散步”。每日巩固可形成“近期运动安排”主题并连起计划、执行和调整。每周复盘可说计划发生变化，不能说已完成每周三跑，更不能自行下医疗结论。

### 场景 B：已有主题拆分，但入口连续

“学习实践”主题长期混合英语练习和编程项目。系统给出两个子主题的成员差异、仍跨主题的笔记及建议理由。本人采纳后，旧“学习实践”仍能定位到新结构；后来日记只增加英语内容时，不再次把两个主题合并。

### 场景 C：纠正与撤权贯穿三端

本人把“已完成课程”纠正为“报名但未学完”。Air 失效原结论及其摘要；网页和手机显示同一修订。若手机离线，只能说明本机已限制旧内容、Air 尚未确认，不能承诺其他端已经更新。撤销该来源的整理许可后，周报和主题摘要不能通过旧缓存继续呈现依赖结论。

### 场景 D：Air 缺席一个周期

Air 离线两天后恢复：显示恢复处理与待覆盖期间；已有有效记忆仍可查。补跑只处理同一版本一次，报告标记覆盖不足；失败停止后明确需要重试，不让进度停留在“后台处理中”。

## 5. 评估建议与边界

先用合成集与获准的少量真实样本建立现有实现基线，再对比新组织层。数据冻结、模型与预算一致，分别报告模型结果和规则层结果；不引用论文性能作为 Riji 保证。

建议至少比较以下维度：

- 来源能否追溯；来源修订/撤权后陈旧内容还能否召回。
- 关联是否有证据、是否错连；相同事件、不同事件与因果是否混淆。
- 回答当前状态与历史变化时是否保留时间和反例；不可回答题能否承认证据不足。
- 同一输入重复巩固时结构是否无理由改变；本人否决和锁定是否持久生效。
- 每日、每周、补跑任务的覆盖率、延迟、成本、失败恢复与前台导师影响。
- 网页与手机能否在短时间内找到“发生了什么、为什么、依据、如何纠正”；三端是否保持同一生效状态。

阈值应在主 PRD 区分硬性正确性门槛与试运行目标。来源越权、原文被改、本人纠正被覆盖、删除后同一版本重生、重复任务提交属于必须为零的阻断性失败；主题命名质量和检索收益需人工标注评估，不应承诺自动全对。

## 6. 后端采用建议

将 A-MEM 作为组织算法方向，在现有 Mem0 权威记忆正文与 SQLite 来源/授权/作业/审计层上增加动态笔记语义、关联和主题版本。是否引入新索引或存储留给架构验证；本 PRD 不以迁移 ChromaDB、部署官方库或重启共享 Colima 为前提。

本文没有检查当前生产进度，也不把前文聊天中的数量或时间当成本次已验证现状。需要在开发/上线验收时重新取有时间戳的基线。
