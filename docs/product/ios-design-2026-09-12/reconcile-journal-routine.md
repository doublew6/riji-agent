# 每日模板、周月复盘与北极星 MIT 的迁移对账

日期：2026-09-12。范围：本仓库中的 README、旧 PRD、能力包、模板读写实现、周期检索和相关测试定义。未读取私人日记、`.env`、真实模板目录、外部私人 skills 或 Air；未运行模型、测试或自动化。本子任务可正常执行。

**用户本轮已明确：按原模板创建每日记录、周报/月报、基于北极星指标生成每日最重要的一件事，首版必须保留。** 这些是本次迁移要求，不再列为待批准范围。实现现状缺口用于确定补齐工作，不能用于把需求移到后续或继续只做自由记录。

## 2. 每日模板必须保留的已知结构

完整真实模板未读取，下表仅是仓库已经确认的标题锚点与用途，不能宣称它等于用户模板全部内容或准确顺序：

| 既有锚点 | 用途 |
| --- | --- |
| `🌅 Morning` | 早晨计划与当日意图 |
| `🎯 Most Important Task (MIT)` | 当日最重要的一件事 |
| `📋 Today's Tasks` | 待办与习惯 |
| `💪Workout` | 运动数据；架构要求表格安全写入 |
| `🌆 Evening` | 晚间事件、状态和工作记录 |
| `🪞 Self Reflection` | 反思、情绪和原则复盘 |
| `📚 Daily Learning` 及其对应项 | AI / Quant / 其他学习 |
| `🧠 Notes` | 无法可靠分类的自由记录；AI 讨论结果在此独立标记 |

pack 的 daily 描述还包括 sleep，weekly 描述为目标、学习、关系、精力与下期优先事项，monthly 描述为主题、进展、资源分配与战略优先事项。这些只是用途说明，不是实际表格列名、标题级别或模板正文；iOS 应展示真实模板中已有的区块、字段、表格与未知 frontmatter，不能据这些描述重造另一套模板。

现有实现的实际契约：

- `instantiate_daily` 只替换 `{{date}}`、`{{title}}`，不执行 Obsidian Templater/Dataview/脚本。不应自动承诺所有模板宏在手机可运行。
- `append_to_section` 按 Markdown 标题定位，先精确匹配、再允许部分标题匹配；保留其他区块，不能找到标题则报错。保留行为见[模板测试](../../../tests/test_drafts_template.py)。
- writer 固定写 `daily/YYYY-MM-DD.md`；已存在文件按当前内容追加，目标不存在才实例化模板；无模板/无锚点/读写失败不得生成半文件。覆盖见[writer 测试](../../../tests/test_drafts_writer.py)。
- 周/月需要独立的周期身份和模板写入契约，不能把周报日期塞进 daily writer 后宣称已生成周报。

## 3. 当前“命令”与周期来源边界

| 名称 | 仓库里的实际作用 |
| --- | --- |
| `draft_daily_entry` → `commit_draft` | 已有受限工具链；预览后本人明确确认再写日记。旧示例确认表达为“确认保存” |
| `list_periods(kind, date_from, date_to)` | 只读列出获准且有界的日/周/月文件元数据；没有报告生成副作用 |
| `weekly-review-from-daily` | pack skill ID，描述基于每日证据和可选健康/运动记录形成周报，需确认；不是已实现 CLI 命令 |
| `monthly-review-from-weekly` | pack skill ID，描述基于周报加精确日期的日记证据形成月报，需确认；不是已实现 CLI 命令 |
| `create-daily-journal` | planned automation ID：每天 00:05，从配置模板创建，不覆盖既有文件；只是元数据 |
| `create-previous-weekly-review` | planned automation ID：周一 08:15，为上一 ISO 周起草；只是元数据 |
| `create-previous-monthly-review` | planned automation ID：每月 1 日 08:20，为上一个自然月起草；只是元数据 |

pack 将 `RIJI_TIMEZONE` 列为可选配置，上表时刻不是已经部署的用户日程。用户要求首版保留周期能力，不等于要求本轮自动安装这些时间表；App 先提供明确的创建/生成入口并保留可配置自动触发边界。

周期证据须在 iOS 新要求中明确：

- 周报目标是**选定 ISO 周的准确起止日期**；月报目标是**选定自然月**。可查看本期/上期，生成目标不能随当前日期悄悄变化。
- [periods.py](../../../src/riji_agent/retrieval/periods.py)已按 `date.isocalendar()` 计算周标签、按自然年月计算月标签；这仅证明时间线分桶，未证明周期报告范围算法已实现。
- 日记解析日期为 frontmatter `date` 优先、文件名中 `YYYY-MM-DD` 回退。`2026-W02` 或 `2026-01` 名称本身不被当前日期正则解析为某个完整日期。示例周/月文件显式设置了 1 月 11 日、1 月 31 日的 date；不能把一个文件元数据日期当成整段报告覆盖范围。
- 月报跨月周需仅归入目标月份的日记证据；既有周报可作二级整理来源，不能连同相同日记重复算作两次经历或把一整段跨月周当成本月事实。
- 缺日记、未下载、private/none/local 排除、来源读取失败、结果上限必须分别显示；不能把可见证据不足变成“这周什么都没做”。
- 周/月 AI 复盘是带来源的派生总结，不能因为用户确认保存就变成新的独立事实来源，或自动扩展私人来源授权。

## 4. 北极星与每日 MIT 的证据和设计缺口

唯一可直接复用的仓库锚点是 `🎯 Most Important Task (MIT)`；没有找到北极星实体、字段、来源读取器、候选排序、日生成器或相应单测。当前受限工具可以把用户已确定的 MIT 作为早晨计划写到该锚点，但这与**基于北极星生成候选**是两个能力。

为保留用户原工作流，新 PRD 至少需要说清：

1. 从本人已配置/同步的北极星定义读取当前指标、目标与时间范围；展示来源与版本。未配置或过期时请补齐指标/选择依据，不能猜一个指标或跳过此功能。
2. AI 使用获准的北极星、近期实际进展、未完成承诺和当天约束，提出**一个主要 MIT 候选**；说明它对哪个指标有何关系、今天的可完成产出和完成判据。不能把指标数值未知误写成 0，或编造健康/任务连接器数据。
3. 用户可以改写、换候选、接受或自己填写；接受后预览写入每日 MIT 原锚点，已有当日 MIT 不被新生成静默替换。
4. MIT 的“建议”“已采纳计划”“实际完成/未完成/调整”分开；确认保存不代表已经做完。晚间反馈进入日记，周/月复盘再用实际执行证据反推指标进展。
5. 用户更改北极星或来源版本后，未确认 MIT 候选失效/待重评；已保存历史 MIT 保留当时目标版本，不自动覆写。

这些是用户本轮明确要求的迁移设计补齐，不是对生产运行方式的推断。若后续需要复刻外部 skills 的具体算法或原模板内容，应从已授权的模板/skills 文件读取；本提取不读取私人 vault 来猜测。

## 5. 最小迁移验收清单

| ID | 必须完成的首版场景 | 最小可观察结果 |
| --- | --- | --- |
| JR-01 | 首次打开某天，按原每日模板建日 | 日期/标题替换正确，原标题层级、字段、表格与未知属性保留；无虚构记录，重复创建只保留一个文件 |
| JR-02 | 同一天已有日记，新增文字/语音内容 | 展示原模板区块选择和实际追加位置；本人正文、MIT、任务及 AI 区块不被重排或覆盖 |
| JR-03 | 模板未同步、缺失锚点或包含不支持宏 | 保留本地原稿并说明具体缺口；不能默默改用 Notes-only 模板或把未求值宏当正确结果 |
| JR-04 | 周报生成与确认 | 显示 ISO 周及准确日期、来源覆盖/排除/失败；按原 weekly 模板预览，确认写 `weekly` 周期文件；重复确认不另存第二份 |
| JR-05 | 月报生成，含跨月周/闰年/年界 | 准确自然月范围、周/月来源类型清楚，跨月日记裁到目标月份，同一经历不重复计数；按原 monthly 模板确认 |
| JR-06 | 已有周/月报告重新生成 | 保留原报告与所用来源版本，先展示差异；不沿用旧确认静默覆写，不通过 daily writer 伪造周期文件 |
| JR-07 | 基于北极星产生今日 MIT | 展示真实指标来源/版本、今日约束、单个主要候选及完成判据，用户可接受/调整；没有指标时有可恢复的配置入口 |
| JR-08 | 当天已有 MIT、来源变化或用户改写 | 不自动覆盖；新的候选与旧计划分开，预览失效会要求重新核对，确认仍绑定具体版本 |
| JR-09 | 晚间反馈与周月回看 MIT | “打算/接受/完成”不混淆；反馈使用本人实际陈述；周月用事实与有来源的进展，不把 AI 建议当执行成果 |
| JR-10 | 离线/重连/未知保存结果 | 本机模板/草稿可保留；重连核对目标周期、模板/文件/来源版本，未知结果查原操作，所有日/周/月/MIT保存保持类型与幂等 |
| JR-11 | 汇总结果再次进入检索与记忆 | 保留派生总结类型、来源和日期范围；同一事实不因日记→周报→月报被算为多次经历，撤权/删源影响派生结果 |
| JR-12 | App 全流程可发现 | 首页“创建今天日记/今日MIT”、周期复盘入口、周/月生成与差异预览、北极星管理/生成/反馈均有屏；仅支持周/月阅读不能判通过 |

当前已有 `test_packs.py` 验证元数据可发现、skill/automation ID、隐私声明；`test_drafts_template.py` / `test_drafts_writer.py` 验证通用每日模板和原子追加；`test_journal_parser.py` / `test_retrieval.py` 验证日/周/月识别和检索。它们**不覆盖**真实完整模板、周/月生成保存、空白建日、北极星和 MIT 智能生成。上述 JR 清单是移动迁移新增验收目标，不是已通过测试列表。

## 6. 对上轮设计遗漏的修正判断

上轮 67 屏来源审查集中于已列的 FR 与保存/导师/记忆边界，未将 README 和 personal-growth pack 中的日常复盘主线充分带入迁移对账，因此把“日/周/月可读”误当作日记功能已完整覆盖。用户指出的遗漏成立：新一轮应补回**模板建日→北极星对齐MIT→执行记录→周报→月报**，保留自由记录、长期记忆和导师能力，不能用其中一项替代原有日记例行流程。
