# iOS 圆桌对话 · 开发基线 v0.2

## 1. 概要

从导师页进入与主持人的持续对话，需要多个视角时在对话内邀请固定导师。回复、补充、总结和后续反馈都留在当前聊天，不要求先创建标题或填写背景表单。2026-09-20 用户确认两项功能进入开发，采用本稿首版方案；开发授权不代表已部署或通过真机验收。

[Issue #56](https://github.com/doublew6/riji-agent/issues/56) · [全流程页面示意图](ios-feature-review-2026-09-18/wireframe-roundtable.html) · [交互评审入口](ios-feature-review-2026-09-18/index.html)

本地实现及自动化回归已完成；2026-09-21 已更新 Air 并覆盖安装、启动手机新版，见[集成验证记录](../testing/ios-mentor-memory-2026-09-20.md)和[发布核验记录](../testing/ios-mentor-memory-release-2026-09-21.md)。真实圆桌模型链路已验证；结构化报告就绪状态单独记录，本人内容质量及实际使用验收仍待完成。

2026-09-21 真机反馈修正：邀请页的“下一步”和“确认邀请并开始”固定在屏幕底部安全区域；核对页单独展示实际发言者及将分享的材料，可返回修改。讨论分歧支持 1–10 轮上限，默认 1 轮；参考意见仍为各导师一轮意见及主持人汇总。初次比较没有实质分歧时跳过后续讨论；用户停止或达到资料使用限制时也可以提前结束。

## 2. 参与者与决定方式

本人负责确认交互与资料分享范围；产品维护者记录设计；开发维护者实现接口、恢复及测试。日记导师担任主持人，四位固定导师提供不同视角。所有页面使用虚构示例；本次开发沿用已确认原型。

## 3. 背景与依据

已确认总 PRD 的 FR-19–28 要求直接私聊、圆桌、有限参考/辩论和明确保存。Air 已有持久讨论、主持人、材料与执行记录；手机接口目前关闭圆桌，仅有单导师会话。移动端身份、房间检查、历史查询与操作回执仍需适配，不能将能力标志改为 true 就视为完成。

本稿沿用[总 PRD](../PRD.md)、[常驻讨论 PRD](PRD-persistent-mentor-roundtable.md)及[视觉约定](ios-visual-design-direction.md)。旧飞书群的建群/成员限制不直接套成手机表单，也不能通过手机接口绕过来源权限。App 与飞书目前分别保存聊天；本稿不增加消息同步。

## 4. 目标与验收结果

目标是少做设置、直接交流，同时清楚辨认发言者、讨论进度和结论适用条件。

- 首次进入最多经过“导师 → 圆桌”两次点击即可输入；不强制命名或填背景。
- 同一对话跨三次重开后，已确认消息、当前状态和未发草稿正确恢复。
- 测试中重复点击/超时重试不重复发起讨论；停止后的迟到结果不混入新状态。
- 选定材料的来源、接收范围、修订和撤回测试全部通过。
- 五个合成讨论样例逐项检查角色差异、依据、条件及建议性质，不用回复长度代替质量。

以上为验收目标，尚未实测。

## 5. 使用者与使用场景

仅供当前个人使用：先与主持人梳理想法；需要不同意见时邀请导师；过几天反馈执行情况；挑选结果写入日记。不做公众账号、其他真人协作、自动向飞书转发或无人触发的讨论。

## 6. 用户价值

普通输入先由主持人接话，避免每句话都启动全桌。导师发言有姓名与角色，综合结果同时呈现共同点、分歧与适用条件。用户事实、计划、AI 建议与实际执行反馈保持不同性质。

## 7. 方案与页面

### 7.1 主流程

导师入口 → 圆桌聊天 → 与主持人沟通 → 邀请导师 → 核对本次材料及发言者 → 参考/辩论 → 综合结果 → 继续追问或保存选定结果。

底部始终保持“日记／导师／记忆／设置”四项并列。子页可返回原聊天；键盘展开不遮挡输入、停止或发送状态。主要页面及关键状态全部平铺在[线框图](ios-feature-review-2026-09-18/wireframe-roundtable.html)，可逐屏记录意见并本地导出。

### 7.2 功能契约

| 编号 | 要求 | 页面 |

| RT-02 | 普通发送只请求主持人；显示未发/发送中/已接收/回复中/失败，草稿可恢复 | R02–R04、R12 |
| RT-03 | 邀请 2–4 位固定导师，选参考或辩论；明确发言者与可见材料范围，确认后才启动 | R05–R06 |
| RT-04 | 第一版默认只带当前聊天的选定内容；私聊不自动复制，日记/长期记忆须选择并通过原权限核验 | R06、R14 |
| RT-05 | 显示正在发言的导师、已完成内容和整体状态；允许补充、先总结或停止 | R07–R08 |
| RT-06 | 补充改变条件时更新背景版本；旧版本未交付结果不混入新结论，不能盲目续跑未知请求 | R07、R08、R12 |
| RT-07 | 综合结果区分共同建议、分歧、前提和下一步；同题追问复用聊天，重新讨论必须显式触发 | R09、R13 |
| RT-08 | 可看当前背景和对应来源；纠正后旧结论保留当时条件并标记需重评 | R13–R14 |

### 7.3 状态与资料边界

普通沟通与多导师运行分开。每次运行有稳定编号及有限预算；等待、运行、部分完成、完成、停止、未知结果分别展示。关闭 App 不等于停止服务；“停止”必须得到后台确认，等待确认时保留状态。来源失效后不能继续用旧引用，历史显示“依据已失效”而非悄悄删掉一段话。

**首版成员范围：** 沿用既有“主持人＋四位固定导师”；本次只选 2–4 位发言。界面明确材料对全部成员可见，少选发言者不缩小分享范围。未来若改为仅选中导师可见，需要独立房间/上下文设计与新授权，不能仅改文案。

日记保存是本地文档操作：重验目标原文版本，冲突保留预览与原文，不静默覆盖。后台接收结果和本地成功保存是两个状态；取消保存不会删除原讨论。

### 7.4 技术边界与测试

复用 Air 的讨论编排、身份和持久记录，新增设备范围的移动接口及房间适配；不开放管理接口、不复制完整 vault。连接仍由安装流程完成。移动圆桌不得进入飞书投递队列。

API 测身份、材料范围、版本、幂等和撤权；State 测草稿、断线及迟到回包；UI 测邀请、选择、停止、继续与保存预览；真实 Air 用合成材料验证一轮完整讨论。仅界面 fixture 通过不能宣布圆桌接通。

### 7.5 首版采用的方案

1. **入口：** 圆桌置于四导师上方，名称“圆桌”，副标题“先和主持人聊聊”。
2. **材料范围：** 固定全部成员可见，本次按需选择发言者；邀请前展示材料及接收范围。
3. **不同问题：** 保持当前聊天优先，另起不相关讨论放右上角菜单，旧记录只在历史中查看，不新增启动前话题表单。
4. **展示：** 各导师发言按顺序出现，结尾再综合；不默认折叠不同意见，不展示内部推理过程。

以上方案随本次开发确认成为首版基线。OS 新权限弹窗不适用：本功能复用现有安装授权；只有首次保存且尚未选目录时沿用系统目录选择，拒绝不丢讨论。

## 8. 发布与后续

按三步实施：移动身份/会话接口与主持人聊天；邀请/参考/辩论及恢复；保存与完整验收。每步以退出条件安排相对工期，当前不承诺日期。

首版不做跨端会话镜像、全自动长时间讨论、关系图谱和真实飞书群启用。实现后必须同时通过自动化、合成真实模型、手机实际操作验收，才能撤下“尚未开放”。
