## 历史视觉方向（2026-09-15，已被新规范替代）

整体安静、清晰、原生，以日记内容作为页面中心。使用随系统深浅模式变化的背景、正文色和灰阶辅助信息，蓝色仅用于当前选择与主要操作；使用 iOS 系统中文字体和动态字号，靠字重、行距与段落间距建立层级。正文保持连续文档，目录使用紧凑、可展开的文件行；工具页使用简单列表和轻分隔，减少装饰阴影、大卡片与说明文字。日记、导师、记忆、设置在底部主导航并列，设置是第四项，目录不另加设置栏。图标沿用现有 SF Symbols；日记内容自行携带的图片原样呈现，界面不增加装饰插画。主要特征是打开即见今天正文、光标处直接记录，以及与原目录一致的文件树。

以上是后续界面细化的执行方向，不代表当前增量已完成所有视觉与无障碍验收。

## 应用到 Riji

| 参考方法 | 实际约束 |
| --- | --- |
| 从用户喜欢的应用提取模式 | 参考 Obsidian 的正文与目录操作，保留用户原模板、Markdown 和目录层级 |
| 视觉个性放在排版、颜色与细节 | 已确认的切日、主导航和设置位置保持一致，视觉调整不新增操作步骤 |
| 结构与截图共同核对 | SwiftUI/UIKit 实现对照批准的原型与实际 App 截图；若以后采用 Sleek 成品，再核对其对应版本 HTML 和截图 |
| 检查完整滚动内容 | 正文、长目录、键盘弹起和错误/恢复状态分别走查；仅看到首屏不能认定其余内容缺失 |
| 明确实际可用状态 | 服务未接通时显示真实状态；连接管理收在设置中，首页不要求填写模型或密钥 |

## 每个页面的设计验收

- 用合成日记展示普通阅读、编辑、键盘收起与较长内容；页面操作应有足够触控区域。
- 核对字号、行距、留白、图标与主导航的一致性，内容优先于工具说明。
- 检查四个底部入口与设置子页返回；切回日记后正文与阅读位置保留，长目录的文件预览返回不改变树的位置。
- 单独核验深色模式、大字号和 VoiceOver；没有实际证据的项目保持待验收。
- 设计截图使用合成内容。真实日记、私人模板、记忆及目录信息继续保留在本地，不能作为外部设计服务的输入。
