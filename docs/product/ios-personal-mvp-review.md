## 已确认的范围

- 本版仅供本人使用，Air 继续作为本人后端；公众注册、多用户产品、订阅收费与公共服务运营不属于本版。
- 单用户仍需可信设备访问、凭据保护和既有来源权限；不能公开私人管理接口。沿用本人现有记忆与导师身份，不因 App 接入重新初始化历史。
- 用户随后确认：手机 App 与 Mac Obsidian 编辑的是同一套由 iCloud Drive 同步的 Markdown 文件；Obsidian 是编辑器，不另设一套 Obsidian 专有日记。文件传输沿用 iCloud，不再把 App 自管日记与 Air 双向同步作为本版目标。此项是目标确认，当前只读目录尚未变成原位编辑。
- 保留已有要求：Obsidian 原模板和目录、正文直接编辑与 Markdown 排版、周记与月记、北极星与每日 MIT、长期记忆、单导师与多导师互动。导师与圆桌都直接进入聊天，不设问题或话题管理前置步骤。功能细节需在原型中逐项确认，不能因缩减为个人版而默默删除这些能力。
- 语音优先核查无按量识别费用的方案；没有适用方案则暂缓语音。免费可用性、中文效果和实际交互未验收前，不把复杂录音功能列为必过交付项。
- 先确认功能与交互，再继续后续功能开发。保留现有实现和数据；本轮范围记录不删除或禁用已有录音，不关闭旧程序，不改变 Air 生产配置。

## 已确认的 iCloud 文件关系与冲突原则

App 通过系统文件选择与授权打开本人既有的 iCloud Drive 目录，编辑该目录内 Markdown 的设备端副本，由 iCloud 将变化传播到其他设备。Mac 上 Obsidian 打开对应的同一文件集合。已有原模板、目录结构和文件名保持；不移动库，也不以测试迁移覆盖真实文件。设备未下载的文件、离线缓存和目录授权仍需真机验证。

iCloud 文件同步不是实时共同编辑，也不保证自动合并 Markdown 语义。Apple 文档说明 iCloud 可提供冲突版本并通知文档 App；App 需实现冲突策略。Obsidian 官方所述 Markdown 自动合并属于 Obsidian Sync 功能，不能据此推断 iCloud 提供相同行为。用户在得到解释后回复“同意。继续”，确认以下处理原则并进入原型走查；具体布局与文案尚未确认。

已确认原则：正常保存无需弹窗；外部更新到达且没有本机未保存编辑时刷新正文；存在未保存编辑或冲突版本时，先保留可用双方版本，再让本人比较并选择保留或手动合并。不单按修改时间静默舍弃一方，不承诺所有外部编辑器产生的冲突一定可被系统完整找回。实现验证需同时覆盖本机编辑期间的外部文件变化与跨设备 iCloud 冲突。

技术候选是系统文档/文件协调和版本接口（例如 UIDocument、NSFilePresenter、NSFileCoordinator、NSFileVersion），具体采用方式需在真实授权目录上验证，尚未实现或定案。只标记本机保存成功，不能据此显示所有设备同步完成。

Air 后端拟消费同步到本机的日记版本，按原权限进行记忆提取与导师服务；Air 实际下载目录、文件可用性和版本衔接仍需核验，本轮不变更部署或新增日记同步通道。Mem0/SQLite 等运行数据库继续留在 Air 的既有运行存储，不因此放入 iCloud Drive。文件经 iCloud 同步不改变既有模型使用授权。

依据（2026-09-14）：[Obsidian 文件存储](https://obsidian.md/help/Files%2Band%2Bfolders/How%2BObsidian%2Bstores%2Bdata)、[Obsidian 的 iCloud 同步说明](https://obsidian.md/help/sync-notes)、[Obsidian Sync 冲突处理](https://obsidian.md/help/sync/troubleshoot)、[Apple UIDocument 冲突处理](https://developer.apple.com/documentation/uikit/uidocument)。本轮仅核查官方文档与现有代码，没有在真实日记上制造冲突或测试写入。

## 语音可行性核查

“免费”在此指无需购买语音服务或支付识别 API 调用费，不代表没有设备、存储、开发或维护成本。语音转文字与后续 AI 整理分别评估，不因转写免费而承诺 AI 调用免费。

| 方案 | 已知能力 | 本版建议与待核查项 |
| --- | --- | --- |
| iPhone 键盘听写 | 系统输入功能，可在文本输入位置听写；多种语言可在设备处理，具体可用性有差异 | 优先验证短句直接进入正文、中文与标点、修改和重开保存；系统听写不等于 App 保留原始录音 |
| Apple Speech | 既有代码使用中文 SFSpeechRecognizer，并强制 requiresOnDeviceRecognition；iOS 26 另有 SpeechAnalyzer/SpeechTranscriber 设备端方案 | 先确认本人机型、系统、语言资源与实际效果；现有恢复审查和真机缺口仍未关闭，不自动更换框架 |
| Air 本地 whisper.cpp | 开源项目支持 macOS、Apple Silicon 与离线运行，无需购买远端识别调用 | 备用候选；音频需明确传到 Air，实际模型、中文质量、延迟和对旧服务的资源影响未测。本轮不安装、不下载模型、不部署 |

依据（2026-09-14 核查）：[Apple 听写](https://support.apple.com/zh-cn/guide/iphone/iph2c0651d2/ios)、[Apple SpeechAnalyzer](https://developer.apple.com/videos/play/wwdc2025/277/)、[whisper.cpp 官方项目](https://github.com/ggml-org/whisper.cpp)。

当前证据：只完成官方资料和本地实现核查，没有新增录音、转写调用或真机测试。机型与 iOS 版本尚待用户提供。建议先测试系统听写；独立录音入口是否保留为首版体验仍待确认，不能把此建议写成用户已批准。

## 三轮交互确认

### 第一轮：功能和文件关系

提供一页功能表，每项列出入口、用户操作、可见结果、数据落点和实现状态。以现有模板结构和合成示例展示，不把私人原文嵌入可分享原型。

文件关系已确认采用上述同一 iCloud 文件集合。仍需确认离线修改、跨设备修改冲突的具体交互，以及 App 与飞书如何衔接同一导师的聊天历史。当前外部目录只读与 App 自管日记写入是现状，不是目标文件方案。

通过依据：用户逐项确认范围与文件行为；未决问题保留可见，不能由“原型能点击”推断已解决。

### 第二轮：完整可点击原型

制作可在 Mac 浏览器离线打开的手机原型，默认今日正文，展示日记、导师、记忆三个入口。主要按钮能演示完整跳转，正文与记忆等数据使用明确标识的合成示例；原型不访问私人文件、不调用模型、不冒充真实功能。

| 走查场景 | 要看到的完整结果 |
| --- | --- |
| 按原模板记录今天 | 找到位置、输入或修改、保存状态、离开后返回 |
| 打开目录与旧日记 | 原目录层级、展开折叠、阅读/编辑边界、返回原位置 |
| 北极星与 MIT | 查看指标、生成建议、修改确认、记录实际反馈 |
| 周记与月记 | 原目录直接打开；手动生成时选择周期、看原模板草稿并保存；沿用 Air 既有任务 |
| 导师私聊 | 点导师直接输入、回答、切换导师后恢复各自历史与草稿 |
| 多导师互动 | 直接聊天、按需邀请与材料范围、参考/辩论、停止、继续聊天和结果保存 |
| 查看和管理记忆 | 分类、证据、纠正/删除、变更后的状态 |
| 断网、Air 不在线与冲突 | 本机可用内容、待处理状态、双方版本和恢复入口 |
| 语音（条件项） | 系统听写或候选免费录音方案的操作区别；未通过可用性验证时可暂缓 |

用户按场景亲自点击，反馈用“页面 → 操作 → 实际感受/问题 → 希望怎样”。每轮修订标记已解决与待确认；不只检查静态页面好不好看。

通过依据：核心场景均能找到入口并走完；用户明确认可操作路径。旧全流程 HTML 保留为历史设计参考，不作为本次个人 MVP 已确认原型。

### 第三轮：关键手感与技术验证

用少量关键页面确认排版、密度和控件。浏览器只能演示流程，正文光标、Markdown 编辑、中文输入、滚动、键盘遮挡、听写与真实目录权限必须在原生 App/真机验证。

在确认后续开发前，以小范围技术验证回答文件关系、Air 连接、身份映射和免费语音是否可行；任何对既有服务的部署变更继续遵守项目规则，不以原型确认代替生产验收。

通过依据：关键体验得到用户确认，技术未决项有证据或明确暂缓；然后统一修订 PRD、原型和验收清单，记录版本及用户确认。当前确认了个人范围、语音费用条件和 iCloud 文件同步路线，尚未通过完整体验确认。

## 开发后的验收方式

每次只交付一个已确认的完整使用场景，提供桌面启动方式和对应验收步骤。自动化测试负责保存、隔离、错误恢复等行为；用户走查负责体验是否符合预期。新反馈先更新交互与验收标准，再判断代码影响。已通过测试不能替代功能体验确认。
