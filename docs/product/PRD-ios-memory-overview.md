# iOS 结构化记忆概览 · 开发基线 v0.2

## 1. 概要

记忆首页改为主题化概览，让本人快速理解系统对自己的认识，而不是先浏览数百条原始记录。按需进入分类、摘要及证据，仍能纠正和追溯。2026-09-20 用户确认两项功能进入开发，采用本稿的首版方案；开发授权不代表已部署或通过真机验收。开发与测试不修改真实记忆、不重开停止的历史整理。

[Issue #57](https://github.com/doublew6/riji-agent/issues/57) · [全流程页面示意图](ios-feature-review-2026-09-18/wireframe-memory.html) · [交互评审入口](ios-feature-review-2026-09-18/index.html)

本地实现及自动化回归已完成；2026-09-21 已更新 Air 并覆盖安装、启动手机新版，见[集成验证记录](../testing/ios-mentor-memory-2026-09-20.md)和[发布核验记录](../testing/ios-mentor-memory-release-2026-09-21.md)。真实圆桌模型链路已验证；结构化报告就绪状态单独记录，本人内容质量及实际使用验收仍待完成。

## 2. 参与者

本人确认哪些分类有用、概览是否准确；产品维护者记录信息层级；开发维护者负责证据、权限、版本与测试。示例都是合成内容，不能视为真实用户画像。

## 3. 背景

Air 已保存原始记忆、按主题整理的 JSON 报告、比较建议和待验证观察，电脑端 Memory Review 有“认识地图”。手机当前只读取逐条记录，还没有读取和展示报告。

依据：[总 PRD](../PRD.md) FR-29–35、[长期记忆说明](../long-term-memory.md)、[视觉约定](ios-visual-design-direction.md)。结构化 JSON 不等于知识图谱；现有后端没有完整实体关系图，本稿也不假称已具备。

## 4. 目标与验收结果

- 进入“记忆”后首先看到主题与简短认识，首页不逐条铺开原始记录。
- 从首页至任一摘要的依据，最多三次点击；用户能辨认事实、计划和观察。
- 纠正、删除、撤权或来源变化后，依赖的旧摘要不再作为当前认识展示。
- 整理失败、部分覆盖、无可见内容、离线旧副本四种状态在测试中均可区分。
- 用户评审确认主要分类名称、信息量和纠正入口；测试不以分类数量或记忆条数代替质量。

以上为验收目标，并非已完成数据。

## 5. 使用者与场景

个人日常查看“系统目前如何理解我”、某个目标有哪些依据、哪些认识需要更新。偶尔才进入原始条目进行纠正；专业维护、批量处理与完整任务日志主要留在电脑端。

## 6. 用户价值

第一层看主题，第二层看归纳，第三层才核对原始依据。减少手机上的信息负担，同时保留来源和纠正能力。一个事实支持多个摘要时不重复累计为多个独立经历；不把计划、讨论建议或导师推断当成已经发生的事实。

## 7. 方案与页面

### 7.1 信息层级

记忆概览 → 主题分类 → 一条认识的摘要与依据 → 原始记忆/日记来源 → 纠正或复核。

底部保持“日记／导师／记忆／设置”，进入详情后可返回原分类位置。所有关键状态平铺在[线框图](ios-feature-review-2026-09-18/wireframe-memory.html)，并提供逐屏反馈及本地导出。

**首页方案：** 展示六个生活主题，另设“导师观察”入口；每个主题给一条代表性摘要和更新时间。分类名称复用后端：偏好与习惯、目标与计划、工作与学习、关系与生活、经历与变化、其他认识。导师观察按导师隔离，避免拼成一个貌似共同确认的画像。

### 7.2 功能契约

| 编号 | 要求 | 页面 |
|---|---|---|
| MM-01 | 首页主题概览，不默认展示逐条记录；卡片是有证据的实际整理结果 | M01–M02 |
| MM-02 | 分类页展示多个简短摘要，区分当前、历史阶段、计划和待验证观察 | M02–M03、M13 |
| MM-03 | 每条摘要可展开来源、证据时间、限制；无足够依据不补写虚构画像 | M03–M04 |
| MM-04 | 原始记录作为深层入口保留搜索、来源、纠正、复核、归档/删除 | M04–M06、M12、M16 |
| MM-05 | 共享事实与导师私有观察分开；切换导师不默认跨范围综合 | M13 |
| MM-06 | 显示整理时间、真实覆盖及部分失败；允许请求新的有界整理，不能隐含重开停止的历史批次 | M07–M08 |
| MM-07 | 修改或撤回证据后旧摘要隐藏或标为待更新；新旧版本不混合 | M08、M11 |
| MM-08 | 待复核页呈现疑似重复、冲突或状态变化，带双方证据；不自动合并/删除 | M09 |
| MM-09 | 离线展示明确标时的可用副本；过期授权、已知撤回内容不能回落到旧缓存 | M10–M11 |
| MM-10 | 区分未整理、无数据、权限不允许、服务失败；重试保留当前阅读位置 | M07、M10、M14–M15 |

### 7.3 纠正与来源规则

“这条认识不准确”先展开相关证据，让本人选择纠正哪条原始记忆，核对修改前后差异后提交。摘要本身是派生结果，不直接改成一条新的无来源事实。纠正成功立即使依赖摘要失效，并显示待整理；不能先显示新摘要再等待服务确认。来源已变时先比较，不用旧版本覆盖新内容。

归档退出召回，可恢复；删除保留原日记并遵循现有删除抑制。原始记录的删除确认明确对象，取消不改变内容。观察保留支持证据、反例、限制和所属导师，不自动升级为共享事实。

### 7.4 数据与技术约束

复用 Mem0 原始记忆及 Air 的版本化整理报告，新增设备权限内的概览/分类/证据投影接口，不把整份管理报告原样暴露给手机。先做主题、版本、范围和证据过滤，再生成响应；分页必须绑定版本，变化后重读而不是混页。失败/停止项数量与成功覆盖数量分别计算，不能由总数差值推测仍在处理。

界面渲染本身不触发新的模型处理；主动整理仍受原用途授权、内容预算和停止规则限制。概览不是新增权威存储，缓存可重建；不复制原 vault，不修改既有自动捕获或重试规则。

API 测不同用户/导师、无效证据、分页与撤权；State 测纠正后失效、离线和乱序返回；UI 测概览→分类→证据→纠正→待更新完整流程；真实 Air 合成报告核对投影与来源。旧条目管理仍保留回归。

### 7.5 首版采用的方案

1. **首页形态：** 主题卡片，每类一句有证据的代表性认识。
2. **导师观察：** 单独入口，明确所属导师。
3. **优先内容：** 保留“最近变化／待复核”两项轻量入口，不抢主题位置。
4. **图谱：** 先确认分类与证据体验；关系网络图作为以后独立方案，不为首版引入图数据库。

使用既有服务与目录授权，无新 OS 权限申请。打开原日记若权限失效，提供重新选择或返回证据，不删除当前概览。主题为空不能靠模型临时猜内容。

## 8. 发布与后续

按三步推进：安全报告投影和版本过滤；概览/分类/证据界面；纠正、复核及缓存失效验收。每步通过 API、状态及 UI 测试后再接真实 Air，具体时间由实施拆分确定。

首版保留可追溯的结构化概览，不做全库自由推理、自动冲突裁决、无证据画像、批量改写记忆或跨导师自动综合。最终验收需本人确认首页可理解、摘要有用且纠正入口易找。
