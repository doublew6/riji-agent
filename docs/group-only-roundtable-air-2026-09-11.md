# 固定导师群：权限发布与 Air 验证记录

日期：2026-09-11。关联 Issue：#43。

本文记录本轮实际证据；软件回归通过不等于飞书端到端验收通过。

## 本轮功能边界

固定群以 `group_only` 模式接管：只使用接管后该群内本人发送的问题、补充，以及该问题产生的 AI 内容。旧飞书聊天记录、网页补充、私聊、私人日记和长期记忆不进入群讨论。普通消息由主持人回应一次；本人明确要求全桌参考或辩论后才启动多导师流程。

成员或群配置变化会使讨论暂停。重新核验仅恢复到停止状态，需要本人明确继续；不会自动启动模型。每次模型调用和发送仍检查当前群成员及管理权限。生命周期转发失败不能作为连续观察的证明，`history_restricted` 和 `continuity_verified` 不会被手工设为已验证。个人来源群讨论仍保留原有的更严格门槛。

AI 讨论结果可交给原日记导师私聊确认，保存到单独标注的 AI／导师讨论区域，不自动写入本人日记正文。

## 已核验的群状态

初次部署时现场 UI 显示：一名本人用户、四位导师机器人；邀请和编辑仅限群主／管理员，进群验证开启，公开搜索关闭，新成员历史消息可见关闭，所有现有群成员可发言，管理员列表为空。

初次部署的真实接口确认四位导师均在目标群，原主持人当时尚未入群。网页端的群机器人页、成员添加页及原主持人资料卡均没有可用的添加机器人入口；Air 原生客户端受系统辅助功能权限限制。本轮没有通过放宽邀请权限、提高机器人管理权限或修改系统权限来替代入群操作。

以上 UI 记录不能替代后端成员证明，也没有据此创建讨论授权。本人随后通过客户端加入原日记导师，续验结果见下节。

## 主持人入群后的真实续验

本人确认加入原日记导师后，真实 API 核验五个应用均在群；原主持人读取到一名本人用户、五个机器人，owner 与原应用 allowlist 一致。邀请／编辑仅群主，分享禁止，进群需审批，全部现有成员可发言，无额外管理员。

通过真实已登录飞书网页版向目标群发送一次 `receipt_only` 短期接收挑战，后端状态为 `received`。挑战仅验证原应用、本人及目标群的真实接收，不授予日记或模型权限。模型步骤、artifact 和 delivery 数量均未增加。

首个虚构案例在接管时被第二次成员核验拒绝，错误为 `group_room_unverified`；没有创建问题或调用模型。现场只读探针确认八项 API 均成功、配置版本不变、五个机器人完整；成员接口原始 JSON 的 `member_total=1`，却在 `items` 中重复返回同一名本人的两条记录。两条记录均为正确的 `open_id` 类型和相同正确租户，原始 JSON 与 SDK 解析一致。

已将这项兼容问题修复为逐条验证身份后去重，再核验完整的唯一成员集合。额外成员、身份／租户冲突、人数不符、不完整分页、循环分页及群设置变化仍被拒绝。新增 26 项原始响应到 SDK 解析的回归，成员契约共 108 项通过；本地完整候选 1369 项通过、4 项跳过，Air 同一候选 1363 项通过、10 项可选跳过。开发目录保留并行改动，并通过 244 项交叉测试。只替换成员检查与相关测试两个文件，备份位于 Air runtime 的 `deploy-backups/20260911-members-dedup-v1/`；只重启 riji-agent 主服务，原主持人与四位导师接收器 PID 均保持不变，健康接口返回 200。

修复后重新登记接管，并通过飞书客户端发送新的真实消息，没有重放第一次失败的事件。已通过的现场步骤：

| 步骤 | 实际结果 |
| --- | --- |
| 普通问题 | 原日记导师生成一个 `followup`，一次模型请求、一次成功投递并取得飞书回执 |
| 四位参考 | 四位导师各生成一个 `opinion`，主持人生成一个 `comparison`，五条模型输出均成功投递 |
| 参考后请求辩论 | 本例比较结果为无实质分歧，同一场次保留预算并直接生成 `synthesis`；没有冒充多轮交锋 |
| 两轮交锋 | 另起同题场次，明确以虚构案例和两种演练初始立场进行比较；四条观点、一条比较、四位各两轮回应、一条综合建议，共 14 条输出全部送达 |
| 中途停止 | 新场次实际运行后，通过本人飞书客户端发送 `停止讨论`；主持人回执确认停止，执行租约及预算均停止，已发送两条保留、尚未投递的一条取消且发送尝试为零 |
| 结果导出 | 对已完成的两轮讨论执行真实导出接口；v2 校验和正确，保留用户／主持／导师内容及场次记录，剔除群定位字段 |
| 来源与权限 | canonical owner、原 host 和目标群绑定一致；一个用户／五个应用，私人来源为空；所有引用只指向本问题，历史限制及连续性证明仍为 false |

两轮交锋场次使用 14/24 次模型请求、约 345 秒，执行和发送均无错误。实际内容出现对其他导师论据的回应、条件补充和立场修订，最终形成有适用条件的建议；没有把演练初始立场描述为导师自发产生的分歧。完整场次结束后检查无待发送、发送中或状态不明记录。

停止后另取三次只读快照，跨度 60 秒：该场请求保持三次、AI 产物保持三条、两条已发及一条取消均未变化，执行租约与预算未恢复。第四步的 `execution_inactive` 是发出模型请求前的检查拒绝，没有产生第四次计费或第四条模型结果；本次证明停止后的继续执行被阻止，不据此宣称已实测在途模型晚到响应。最终健康接口为 200，27 项本轮发布源码校验一致，六个服务 PID 及受保护配置保持不变，三个项目端口均只监听 loopback。

以上步骤的安全元数据保存在 Air runtime 的 `acceptance/group-only-live-20260911/`，包含主持回应、四人参考、无分歧综合、两轮交锋和停止快照；已完成讨论的 JSON 导出只保存在 Air 私人验收目录。浏览器现场已看到原主持人的综合建议及停止回执。所有发送均来自已登录的本人飞书客户端，没有用伪造 SDK 事件替代真实收发证据。

## 使用方式与验收限度

在现有群中直接描述情况，日记导师会回应一次。发送 `请四位分别给我参考` 启动独立观点及比较；发送 `请大家辩论一下` 延续本场，有实质分歧才展开交锋。`请四位重新讨论` 在同一问题下开启新场，`停止讨论` 停止当前场。`请四位重新讨论，不沿用旧结论` 可在新场重新评估，排除旧 AI 判断；这一特殊说法本轮仅经解析器检查，没有另做真实模型验收。

当前没有群内“换成全新问题”或“清空记忆”的自然语言命令，不能把这些说法当成清除历史或隔离新问题的操作。重新分析仍保留用户事实及完整档案。本轮只验收固定群、同一问题下的复用。

`保存讨论结果` 会提供私聊转交命令；须由本人到原日记导师私聊接收、查看预览并确认，才写入独立的 AI 讨论区域。本轮使用虚构案例，未执行真实日记保存，不能据此宣称私聊写入链路已完成本轮现场验收。携带私人日记／长期记忆的群讨论、真实成员变更中断及事件连续性仍不在此次通过范围内。

模型内容质量仍需单独评测：本例多数回应能对应前文，但有一条发言对自己原始立场的表述不一致；收发及流程验收不代表所有角色叙述均准确。
