**状态**：MVP 基线及已确认增量；主基线 v1.4，导师需求更新至 2026-09-11 / v0.3

**导师增量（2026-09-11）**：[常驻导师群、讨论记忆与日记保存 PRD v0.3](product/PRD-persistent-mentor-roundtable.md)补充并部分替代[导师 PRD v0.2](product/mentor-dialogue-and-debate.md)。**Air 已部署，生产飞书常驻群仍受能力门禁限制。** 同题多次讨论、版本化工作背景与独立 AI 日记结果已完成本地验证、Air 升级检查及单个真实模型隔离样本；生产群主持、真实渠道及完整模型质量验收仍待完成。代码契约见[技术设计](architecture/persistent-mentor-roundtable.md)，交付证据分别见[本地验证](persistent-mentor-roundtable-acceptance.md)和[Air 部署记录](persistent-mentor-roundtable-air-2026-09-11.md)。此前的[实现记录](mentor-implementation.md)、[飞书交付](feishu-mentor-air-2026-09-10.md)和[群探针](feishu-roundtable-probe-2026-09-11.md)保留其历史范围，不能将机器人已发言视为整份 PRD 已交付。

**产品定位**：一个 local-first 的 Markdown 日记 Agent 网关：日记 vault、索引、草稿和审计留在用户本机，外部 Agent / 模型只能通过受限工具访问最小必要片段。默认栈为 Feishu + Hermes + DeepSeek，但架构上允许替换 IM、Agent runtime 和模型 Provider。

## 1. 背景与目标

用户在 Obsidian 或类似 Markdown vault 中持续记录日记、周记和月报，希望以自然对话的方式回顾、提问、梳理个人经历，并可在不同对话中使用不同人设。项目应能服务单个用户的本地私密部署，也应能作为开源组件被其他人接入自己的 IM、Agent runtime 和模型供应商。

产品的核心目标：

1. 使用云端旗舰模型获得高质量的复杂推理、模糊语义理解与长时间线归纳能力。
2. 日记原始 Markdown、索引、对话历史和访问控制始终由用户自己的设备保存和控制。
3. 模型通过受限的本地只读工具，进行多轮、带时间意识的检索，而非只接收一次固定的 RAG 片段。
4. 第一阶段提供 Feishu + Hermes + DeepSeek 的默认开箱栈，用于与不同导师对话和记录日记；同时把 Feishu、Hermes、DeepSeek 视为可替换模块。
5. 基于用户反馈逐步改进检索和人设；人格和日记变更必须先由用户确认，Agent 长期记忆可在普通对话后自动捕获，但必须可查看、纠正、归档和删除。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 主模型 | 默认使用 DeepSeek 云端 API 与 `deepseek-reasoner`；可选 OpenAI-compatible 或 Codex adapter。导师回答与后台记忆分别选择 provider；Codex 使用用户自己的 ChatGPT 登录和套餐，具体边界见第 16 节。 |
| 本地模型 | 不使用 Ollama 运行聊天/推理模型。可选的小型本地 embedding 模型只用于语义索引，不参与生成回答。 |
| 日记位置 | 源日记库由 `RIJI_JOURNAL_ROOT` 配置，指向用户自己的 Markdown journal 目录。项目不复制该目录。 |
| 项目位置 | 可安装为本地 Python package，也可从仓库 checkout 运行；运行数据默认位于 `RIJI_DATA_DIR`。 |
| 对话入口 | 默认入口为 Feishu 私聊；IM 层应作为 adapter，后续可替换为其他聊天入口或本地 CLI/Web。 |
| Agent 编排 | 默认使用 Hermes 负责 IM 会话路由、导师选择、定时任务与技能；它只能通过 riji-agent 的受限工具访问日记。 |
| 默认权限 | 只读日记。写入日记或修改标签必须展示变更并经用户确认；Agent 长期记忆允许后台自动捕获，并通过本地 Memory Review 与只读 `MEMORY.md` 审计。 |

## 3. 非目标

- 不追求完全离线推理。
- 不将整个 vault、云端文件上传、云端向量库作为默认方案。
- 不允许模型拥有任意文件系统、终端、网络或自动写日记权限。
- 不让 Agent 在无人审核下自动改变人设或日记原文；长期记忆允许自动捕获，但不得自动删除，且必须保留本地审计和用户纠正入口。
- MVP 不以独立 Web/PWA 作为入口；该能力留给后续阶段。

## 4. 隐私边界

这是“**本地数据控制 + 云端推理**”方案，**not a zero-egress system**，也不是“文字完全不离开设备”的方案。

本地组件负责读取、切分、建立索引和筛选证据。云端模型只会收到：用户问题、当前人设指令、以及本地工具返回的 bounded journal snippets。complete vault、原始 Markdown 文件、SQLite 数据库和 API keys 不会由 riji-agent 上传。

必须实现：

1. 禁用云端文件上传、云端向量库和云端持久化会话。
2. 每次工具调用记录实际发送的片段、来源文件和时间，便于审计。
3. API Key 仅存于本地网关的环境变量，绝不下发给浏览器或手机端。
4. 本地服务仅监听 localhost 或 Tailscale 网络，不开放公网端口。

带有 `private: true` frontmatter 的日记不得作为检索结果或 `read_note` 内容出云。系统还必须遵守最小片段出云、来源审计与不上传完整 vault 的规则。

## 5. 总体架构

```text
Feishu 私聊 / 指令 / @导师（默认 IM adapter）
        ↕  Hermes 内置 Feishu 接入（默认 agent runtime）
Hermes（路由、导师会话、定时任务、技能）
        ↕  受限工具调用
riji-agent 本地网关（人设、权限、审计、共享记忆）
        ↕
本地索引服务（日期/标题/标签/全文/语义向量） ← Obsidian riji Markdown（只读）
        ↕  HTTPS API；仅发送必要片段
DeepSeek 云端模型（默认 model provider）
```

### 5.1 为什么采用 Agentic RAG

传统 RAG 先按固定规则取 Top-K 片段，再让模型回答；它很容易遗漏隐喻、情绪表达和时间转折。

本产品由旗舰模型决定下一步检索策略，但实际搜索仍由本地工具执行。例如用户问“去年下半年为什么工作没有意义”，模型可以先限定 7–12 月，搜索“意义感/疲惫/组织变化”，发现 10 月是转折后，再读取前后数周的日记并形成有证据的结论。

## 6. 本地工具设计（MVP）

所有工具均由本地网关实现、仅可读取经过允许的日记范围。

| 工具 | 参数示例 | 用途 |
| --- | --- | --- |
| `search_journal` | `query`, `date_from`, `date_to`, `tags`, `top_k` | 关键词和语义混合检索，返回片段、日期、标题、来源。 |
| `timeline` | `topic`, `date_from`, `date_to`, `granularity` | 按日/周/月返回主题出现、事件与情绪线索。 |
| `read_note` | `path` 或 `date` | 在检索命中后读取单篇允许的日记。 |
| `find_before_after` | `date`, `days`, `topic` | 分析某一转折点前后的相关记录。 |
| `session_search` | `query`, `top_k` | 查询同一用户、导师与聊天的历史用户原话，返回时间与 `conversation/<id>` 来源；与日记事实分开。 |
| `list_periods` | `kind`, `date_from`, `date_to` | 返回可用日记、周记、月报的时间范围与缺失情况。 |
| `draft_daily_entry` | `content`, `date`, `persona_id` | 从飞书消息生成日记草稿，不写入文件。 |
| `commit_draft` | `draft_id`, `user_confirmation` | 仅在用户明确确认后写入日记并触发增量索引。 |

工具返回必须包括稳定来源 ID，如 `[[riji/daily/2026-06-18]]`。最终回答必须引用实际使用的来源，并区分“日记事实”“模型推断”和“不足以判断”。

## 7. 人设与对话

一个人设是一个独立配置，而不是一次临时 prompt。其配置至少包含：

- 名称、头像、描述和系统提示词；
- 可检索的日记范围与允许使用的工具；
- 语气和回答结构；
- 是否允许追问、挑战用户叙事、给出行动建议；
- 独立会话历史、共享用户事实与导师私有长期观察。

首批建议人设：

1. **温柔回顾者**：注重理解、复述和情绪容纳，不轻易下结论。
2. **直率教练**：指出叙事中的回避、矛盾和可执行选择，保持尊重。
3. **未来的我**：以指定未来视角反思，但不能伪造日记中不存在的事实。
4. **王阳明导师**：以王阳明思想为主要框架，围绕“心即理、知行合一、致良知”等概念，帮助用户从内在动机、真实认知和具体行动之间的关系反思问题。

### 7.1 王阳明导师的知识与表达边界

- 建立独立、可追溯的王阳明思想资料库，优先收录可靠版本的《传习录》及必要的研究/注释资料；资料与用户日记库分开管理。
- 回答时同时可检索日记证据与思想资料：日记用于理解用户实际处境，思想资料用于形成反思框架。
- 使用“受王阳明思想启发的导师口吻”，不得声称自己是真实的王阳明，也不得编造原文、经历、书信或历史判断。
- 涉及具体思想、原文或观点归属时，标明资料来源；无法确认出处时，以概括性表述并说明是现代阐释。
- 不将历史思想包装为医学、心理治疗、法律或投资结论；遇到高风险困扰时，保持支持性并建议寻求合适的专业帮助。

### 7.2 共享记忆与导师隔离

所有导师共享同一份日记库、Mem0 用户事实和运行偏好；每个导师隔离保存其系统提示词、会话历史和导师长期观察。不得将一个导师的私有会话内容或观察自动注入另一个导师的上下文。

## 8. Hermes 与飞书（MVP 入口）

Hermes 是默认 Agent runtime，使用其自带的 Feishu 接入作为默认 IM 路径，不另行开发 Feishu Bot 协议适配器。具体配置以安装时 Hermes 版本提供的官方 Feishu 接入说明为准。后续架构应允许替换 IM adapter、Agent runtime 和模型 Provider。

### 8.1 路由规则

1. 用户在飞书私聊中通过 `@温柔回顾者`、`@直率教练`、`@未来的我`、`@王阳明导师` 或导师选择命令进入对应人设。
2. Hermes 将 `persona_id`、飞书用户 ID 和会话 ID 传给 riji-agent；riji-agent 决定可用记忆、日记权限和工具范围。
3. 同一飞书用户的不同导师会话独立保存；共享记忆仅由 riji-agent 统一读取。
4. 定时复盘和提醒可由 Hermes 的 cron/skill 执行；涉及日记或人设的写入仍需确认，普通对话中的 Agent 长期记忆则进入可审计的后台捕获流程。

### 8.2 飞书日记写入流程

1. 用户发送“记录日记：……”或进入日记记录指令。
2. 导师调用 `draft_daily_entry`，在飞书中返回日期、标题、正文和标签的草稿预览。
3. 用户明确回复“确认保存”后，导师调用 `commit_draft`。
4. riji-agent 写入目标 Markdown 文件、记录审计事件并更新本地索引。
5. 系统返回写入的 Obsidian wikilink；非明确确认、重复事件或群聊消息均不得写入。

### 8.3 飞书安全边界

- 仅允许白名单飞书用户与私聊会话访问日记工具；群聊默认不具备检索和写入权限。
- 校验 Hermes/飞书连接提供的身份与事件签名；对消息事件做幂等处理，防止重复写入。
- 飞书消息与机器人回复会经过飞书服务；因此本方案不满足“任何文字绝不出设备”。
- Hermes 不获得日记目录的直接读写权限；只允许调用 riji-agent 的窄工具接口。

## 9. 自我改进机制

“自我进化”定义为受控、可审计的改善，而不是无授权的自我修改。

1. 用户可以标记回答为“有用”“不准确”并写下修正。
2. 普通对话可后台生成 Agent 长期记忆；检索规则和人设提示词改进仍作为候选项。
3. 长期记忆自动写入 Mem0 后可在本地 Memory Review 中审计、纠正、归档或删除；其他系统改进仍需用户查看证据与 diff 后确认。
   Memory Review 同时提供带证据的主题认识地图、语义比较建议和真实处理轨迹。
   新事实与人工修改主动触发后台整理；冲突和疑似重复只形成建议。阶段性记忆
   90 天未复核后降低召回顺序并进入复核列表，支持确认有效及可恢复归档，
   不因时间经过自动删除稳定事实。详细边界见 `docs/long-term-memory.md`。
4. Hermes 的定时任务和技能可生成系统改进候选项；这些候选项仍必须由用户审核后才可生效。

## 10. 用户故事与验收标准

### US-01：带来源的日记问答

作为用户，我想询问过往经历并查看依据，避免 AI 编造。

**验收**：回答中列出使用过的 `[[riji/...]]` 来源；没有来源时明确说“日记中未找到足够证据”。

### US-02：复杂时间性回顾

作为用户，我想问“去年下半年”“某件事发生前后”的变化。

**验收**：模型会调用时间范围工具，必要时多轮检索；回答注明时间窗口与转折点依据。

### US-03：多个人设

作为用户，我想在不同对话中选择不同人设，且它们互不混淆记忆。

**验收**：人设拥有独立提示词和会话/长期记忆空间；切换人设后不泄露另一人设的私有记忆。

### US-04：飞书中的导师对话与日记记录

作为用户，我想在飞书中和指定导师聊天，并通过同一入口写日记。

**验收**：飞书私聊可稳定路由到指定导师；日记写入必须经过按模板区块生成的 patch 预览和“确认保存”，且写入结果可回链到 Obsidian。

## 11. MVP 实施范围

### 阶段 1：可用的私密问答

- Markdown 日记增量索引；
- 日期、标签、全文检索与本地语义检索；
- Hermes + 飞书内置接入；
- 多导师人设、单飞书用户、Mem0 共享事实、导师私有观察与隔离会话；
- 王阳明导师及其独立、可引用的思想资料库；
- 旗舰模型的工具调用循环；
- 飞书日记草稿、按模板区块定向追加、确认写入、引用来源与审计日志。

### 阶段 2：日记 Agent 体验

- 多人设与独立记忆；
- Timeline/前后对比工具；
- 独立 Web/PWA + Tailscale（作为飞书之外的可选入口）；
- Memory Review 校勘界面与只读 `MEMORY.md` 快照。

### 阶段 3：受控的主动性

- 周/月复盘草稿；
- 用户批准的日记写回；
- 扩展 Hermes 的定时任务与技能候选生成。

## 12. 初步技术栈

| 层级 | 选择 |
| --- | --- |
| 本地 Agent 网关 | Python + FastAPI |
| 日记解析 | Python Markdown/frontmatter 解析器 |

| 私网访问 | 供本地开发和后续 Web/PWA 使用的 Tailscale |
| 本地持久化 | SQLite（会话、配置、队列、审计）+ Mem0/PostgreSQL/pgvector（Agent 长期记忆） |

## 14. 日记长期记忆增量范围（2026-09-09）

对应维护者专项 PRD v1.2 和 [Issue #40](https://github.com/doublew6/riji-agent/issues/40)。本阶段保留 Obsidian、飞书、模板及严格草稿确认，把日记形成记忆的能力补齐：

- 显式授权日记目录区块，递归发现历史文件、形成初始记忆，持续补入新增、编辑、删除及停机期间变化；显示真实覆盖与失败状态。
- 结构化提取及本地验证，相关旧记忆检索，区分重复、补充、状态变化、冲突和相关经历；保留原始时间、证据、人工纠正和隔离规则。
- 有界跨批次整理，支持、反例与条件明确的观察参与回答；来源撤回即停用对应依据。
- 本地 Review 进度、暂停 / 继续 / 重试、纠错、选择遗忘范围、免费导出和恢复。

不包含外部对话导入、独立客户端、付费系统或多哲学家辩论。核心记忆数据继续由用户保管；商业路径单独维护，不阻塞本次实现。具体默认值及操作见 [功能说明](journal-memory.md)，36 项专项场景与真实模型验证边界见 [验收记录](journal-memory-acceptance.md)。代码、模型质量和 Air 实机验收分别记录，不能互相替代。

上述排除项针对本节日记长期记忆增量。下一阶段的导师沟通与多导师辩论另见第 17 节草案，不追溯扩大 Issue #40 的实现范围。

## 15. 隐私权限与数据流增量（2026-09-09，v1.3）

用户已确认：本地持有数据、按范围授权云端处理、敏感内容单独控制；先完善权限和显著展示，再启动既定 Notes 范围的真实历史初始化。此授权不扩大日记目录、日期、区块和预算，不授权外部对话导入或全库上传。

### 15.1 产品承诺与三级权限

“本地保存”表示权威日记、记忆、来源关系和任务由用户持有，不表示内容从未离开设备。用户自己的 iCloud 同步和备份也可能保留副本；本地部署不是零出云或零留存承诺。

| 权限 | 原始日记 | 日记提取、记忆整理及导师使用 |
| --- | --- | --- |
| 不参与记忆（none） | 原文件保留，不自动修改 | 排除自动提取、检索出云和后续记忆使用；已有条目保留本地供管理，永久抹除需另行删除 |
| 仅本地（local） | 原文件保留 | 不发送到云端；当前没有本地生成模型，因此跳过云端提取，可本地查看/手动维护已有记忆 |
| 允许云端（cloud） | 原文件仍由用户保存 | 仅在用户授权的用途、来源范围、模型接收方和预算内处理 |

文件在 YAML 属性中设置 `memory: none/local/cloud`；`private: true` 始终排除。没有显式属性的内容遵循总授权，不代表整个 vault 获得许可。未知权限值按排除处理。

段落使用 `<!-- riji-memory:local -->` 或 `<!-- riji-memory:none -->` 到 `<!-- /riji-memory -->` 标记；未闭合时保守排除后续内容，嵌套不能放宽外层限制。标记只用于读取过滤，不改写日记内容或模板。Memory Review 的每个记忆卡片直接展示和修改该条记忆的权限。

派生内容继承来源限制。来源撤权后，相关记忆、关系判断及派生观察不得继续出云；其他来源或人工修改不能静默解除限制。单条记忆的“允许云端”不能覆盖来源排除或总授权。

### 15.2 授权用途与生命周期

历史初始化、新增/修改的增量提取、云端整理相关记忆、导师回答使用日记记忆分开选择。一次授权后，范围内后台自动运行，无需每篇确认。

历史范围绑定保存授权时已发现的文件片段版本；新文件或修改后的版本受增量开关控制。仅扫描文件不调用云端模型。授权绑定本地来源、归属、区块、日期、预算、提取和回答模型接收方，以及允许使用日记记忆的导师集合；这些配置变化后重新授权，不能沿用旧授权扩大处理。

- 暂停：停止新的日记提取和主动整理调用；已有记忆仍按召回授权使用。
- 撤回日记授权：暂停处理，并停止新的日记派生记忆出云使用；本地查看、纠正、导出和删除仍可用。
- 原生聊天捕获、当前消息交给模型以及飞书消息传输是独立数据流，不能让用户误以为撤回日记授权等于停止所有 AI 调用。
- 原有受限日记问答继续遵守自己的权限和预算，三级来源标记同样约束这些工具；新增自动提取授权不扩大原问答范围。
- 已发出的请求无法撤回；返回结果写入前再次校验权限。暂停或撤回不等于清除第三方留存、原日记或用户自己的旧备份。
- 换模型接收方或新增导师后重新授权。购买高级导师不能自动获得整库访问权。

### 15.3 数据流

| 阶段 | 本地数据处理 | 可能离开设备的内容与接收方 |
| --- | --- | --- |
| 发现/扫描 | 读取目录与允许的 Markdown，筛选权限和区块，记录来源版本 | 无模型请求；用户自选同步服务属于独立链路 |
| 提取 | 校验权限、片段和累计预算 | 选中日记原文片段、区块与记录日期 → 配置的提取模型（DeepSeek API 或 OpenAI Codex） |
| 关系判断 | 本地语义检索相关旧记忆、校验来源和权限 | 新候选及引用、相关旧记忆和时间 → 提取模型 |
| 主动整理 | 筛选同用户/导师的有效记忆 | 有界的相关事实、时间与依据标识 → 整理模型 |
| 持久化与向量化 | Air 自托管 Mem0、PostgreSQL/pgvector、SQLite、本地 FastEmbed | 当前向量化不使用云端 embedding |
| 导师回答 | 按权限和当前问题选择相关记忆 | 用户消息、相关记忆及受限工具结果 → 回答模型；发送的消息和回复经过飞书 |
| 管理/导出/备份 | 本地 Review、MEMORY.md、结构化备份 | 无需项目方托管；用户另行分享或同步时属于新的披露 |

每日额度和片段长度用于控制发送量，不能替代敏感性判断；长期摘要可能比原文更集中地刻画个人。由云端模型先读原文再脱敏，不能保护已经发送的原始输入。

### 15.4 明显展示，防止遗忘

权限栏必须包含：当前授权/暂停状态、云端接收方、授权区块和日期、四个用途开关的当前值，以及“查看与修改权限”“暂停/继续提取”“撤回日记授权”入口。使用明确文字，不仅依靠颜色。

权限详情页展示实际数据流、目录、模型、导师集合、预算、授权用途、私密标记用法、原生聊天捕获状态，以及最近日记请求的用途/来源标识/时间/字符量。普通日志和页面审计不复制日记正文。使用中的配置变化后显示授权失效，保存授权后仍由用户明确继续提取。

PRD 顶部同步保留醒目提示，说明本地保存与云端处理的区别，并链接权限入口。查看/修改权限、纠错、导出与删除始终属于免费基础能力。

### 15.5 推断、敏感性和后续增强

继续区分明确事实与待验证观察，不将一次情绪升级为固定人格。自动提取的推断先仅本地保存，由用户在记忆卡片决定是否允许云端使用。跨事实整理的观察仍需来源与反例校验，明确标注不确定性；涉及敏感画像的自动判断和专用逐项确认界面需单独验证，不能声称已有可靠敏感性分类器。

本阶段不以本地大模型替代现有云端栈。可选本地提取模型、姓名/联系方式的本地替换、更多细粒度导师策略作为后续增强；现有凭据过滤不是完整脱敏或匿名化保证。

上线前核实模型服务商具体 API 的留存、训练和删除条款。当前不对用户承诺 DeepSeek API 零留存或不训练；公开隐私政策不能直接当成 API 专项保证。

### 16.2 执行与数据控制

Codex 作为模型 provider 通过本地官方 `codex exec` 接收项目构造的有界上下文，返回回答、受限工具意图或结构化记忆候选。使用隔离的持久登录目录、`--ephemeral` 临时上下文及实际工具禁用，不继承个人配置。日记检索和写入仍由 riji-agent 执行：不得授予 Codex 任意文件、Shell、网络浏览、外部连接器或通用编码工具能力。空工作目录、提示词约束和 read-only sandbox 单独都不能代替实际工具禁用。

每次模型调用使用独立的临时上下文；导师会话、共享事实和隔离观察由 riji-agent 本地组装，不能复用个人 Codex 中其他任务的历史。结构化输出仍须通过原有来源引用、时间、权限、工具白名单和操作校验。模型不能直接修改数据库、日记、模板或确认令牌。

后台记忆与导师对话共享本服务的 Codex 调用调度，排队时导师优先。已发出的后台请求不抢占中断；排队、请求和失败恢复有界，不能无限等待。额度不足、登录失效或模型不可用时，保留本地任务并暂停或退避，页面和日志提供不含正文、密钥的原因；恢复后继续现有任务，不重复写入已成功内容。

后台运行可通过可选的 `RIJI_CODEX_PROXY_URL` 使用用户已有的本机代理，解决 SSH / LaunchAgent 不继承系统代理导致的直连失败。配置按秘密值处理，只接受不带用户名、密码、业务路径或 query/fragment 的 HTTP(S) loopback 地址及显式端口。未设置时保留既有代理环境继承；显式设置时仅作用于 Codex 子进程，并让其 `NO_PROXY` 仅包含本地地址，不修改系统、Feishu 或 Mem0 配置。这是连接到 OpenAI 的部署选项，不增加模型联网工具、不变更日记来源、模型接收方或预算。

使用本机代理的部署依赖该代理可用，项目不管理代理进程。官方账号登录持久保存在运行服务的主机；完成设备授权后不需要授权时使用的浏览器持续在线。代理不可达属于连接故障，不能直接据此认定账号登录失效。

### 16.6 用户确认的预算调整（2026-09-09）

用户明确授权：**日常日记记忆处理每 UTC 日 100000 字符；本次历史初始化不设每日总量上限。** 原 40000 字符规则被此决定取代。单片段 900 字符、同一来源版本累计 4000 字符、Notes 范围、private/local/none 排除、历史/增量/整理/召回四种用途及模型接收方保持不变。

日常上限由 `RIJI_JOURNAL_MEMORY_DAILY_CHARS=100000` 配置。初始化例外由 `RIJI_JOURNAL_MEMORY_INITIALIZATION_UNLIMITED` 显式开启，默认 `false`；本次按用户授权设为 `true`。先扫描，再登记绑定新预算策略的历史授权，最后恢复；固定批次只取已授权 `privacy_history` 证据 ID / 版本与当前有效版本的交集。未扫描或授权名单为空时保持 `awaiting_scan`，空授权后出现的新文件不能自动改判历史。后续重新授权、扫描、重试不扩充已冻结批次；新文件、后来补入的旧日期日记及编辑后的新版本均使用日常预算。

固定批次的提取、关系判断，以及以本批产出记忆为种子的必要有界整理，使用独立的 `initialization:UTC-day` 字符账本，不占日常 100000 字符。旧日账本不清零，也不追溯转移旧请求到初始化账本。普通种子整理和增量仍受日常上限约束；不能因为初始化活跃就让所有后台请求豁免。提示词、原文和相关旧事实继续计量；没有每日总量上限不代表不计量、一次发送完整日记或 Codex 套餐无限。

新策略生效后立即重新开放本批中仅因 `daily_budget` 等待的任务，不等旧次日时间戳，不清空预算、缓存或幂等记录，也不顺便重跑旧失败任务。来源累计上限、权限变化、账号额度、登录、模型和网络故障继续按各自规则处理。

提取达到终态且必要整理完成后，程序持久关闭本次豁免；即使环境变量继续为 `true`，也不能自动启动第二个无限批次。暂停和撤回授权继续阻止相应调用；重启只能恢复既有批次。成功、排除和失败分别呈现，结束批次不能冒充所有来源成功。

Memory Review 显著展示日常已用 / 100000、初始化模式及独立累计量、批次状态和完成 / 未完成数量。初始化按 UTC 日保存账本，页面累计值包含本批各日用量。验收须验证固定清单不扩张、普通增量仍限额、预算等待立即恢复、旧失败不重跑、必要整理有界、结束后不重开，以及权限和 900 / 4000 限制仍生效。实现测试、Air 配置生效与实际队列恢复分别留证，不能由其中一项推断全部历史完成。

已记录的预算实现回归包括：开发机 685 passed、2 skipped；发布测试清单 77 个文件，693 passed、1 warning。此前对全部遗留镜像测试的运行包含 12 failed、697 passed，不能把发布清单结果概括为全部镜像测试通过。真实运行的授权、计量和处理进展需在每次部署中独立验证，具体个人运行快照不进入公开 PRD。

### 16.7 初始化失败恢复与验收（2026-09-10）

Codex 提取、关系判断和整理请求直接携带对应业务 JSON Schema，限制字段、数量及当前允许引用的记忆 ID；应用仍逐项核验原文依据、时间、独立经历、权限与版本。结构校验失败不触发另一个 provider 或无约束的隐式补发。请求预算包含业务 schema；模型输出格式正确不等于记忆事实正确。

一次整理失败后，只在确有已发送种子的持久进度时续排剩余任务。恢复调度保留已有等待时间，不重置成功结果和消费记录；已失败或已发送的同版本种子不能被普通自动选种再次发送。对确认为失败的来源片段，可按 ID 与版本定向重试，保留已提取候选和原预算。成功后同步纠正固定批次的失败计数，不重新开放原批次的初始处理豁免。

整理失败记录仅保存白名单错误分类，用于区分模型接口、输出结构、主题覆盖和独立依据不足；不保存异常原文或失败响应正文。未知原因维持通用失败标记，不能根据后续分类反推旧记录的实际原因。

整理的结构化输出约束须与可用经历一致：观察的支持候选仅来自程序核验为明确经历、且具有有效日记日期的记忆；缺少至少两个候选或不足两个日期时，模型只能返回空观察列表。偏好、计划、原生聊天和周月汇总不能仅凭模型引用成为独立经历。本地仍复核支持与反例的去重、互斥、日期、权限和版本；结构约束不替代这些校验，也不代表对观察内容作了语义确认。

用户于 2026-09-10 进一步确认：本次固定初始化批次中，按失败 ID / 版本显式登记的一次整理恢复，也使用 `initialization:UTC-day` 账本，不设每日总量上限。该规则取代此前将这些恢复计入日常额度的规则。只有初始化配置仍启用、当前范围与冻结批次一致、原种子有首次发送记录、该恢复尚未发送时才可使用例外；不重新开放原批次、不扩充固定清单。新文件、新版本、普通整理和日常增量仍受每日 100000 字符上限约束。

恢复登记和实际发送时间分别审计，保留首次发送记录、既有日常及初始化账本，不清零或追溯转移已发送请求。仅因日常预算等待的有效有限恢复可立即继续；权限、单片段与来源限制、模型额度、认证和网络退避继续生效。每个失败 ID / 版本仅一次恢复；已发送、恢复成功、恢复失败或排除的项不能自动再试。恢复全部达到终态后关闭对应例外，原批次仍保持原有终态语义。

Memory Review 同时展示提取与整理的完成、等待、失败和恢复队列，并突出适用初始化账本的待发送 / 已发送待结果恢复数量、初始化累计量及日常已用 / 上限。原批次为 `blocked` 时，页面可以显示有限恢复额度有效，但不得显示整个初始化重新开启或全部完成；配置关闭、范围不匹配、批次取消或有限恢复已终结时不能显示有效豁免。

验收分为代码回归、真实模型合成样本、真实历史覆盖、人工事实复核和跨会话召回。新增合成验收集与开发调优集分开；评测默认只输出计划，显式启用才调用模型，并记录 provider/model、语料版本、阶段耗时和请求字符。开发者编写的预期答案标记为未复核，不能宣称盲测或人工通过。

## 17. 导师沟通与多导师辩论增量（2026-09-11，PRD v0.3）

用户确认围绕一个问题获得单导师开导、多导师参考与辩论，并采用独立导师入口、私人圆桌群及可迁移架构。2026-09-11 进一步确认长期保留群、由原日记导师主持、分层更新问题记忆，以及将 AI 讨论结果独立保存到日记。最新范围与验收见[PRD v0.3](product/PRD-persistent-mentor-roundtable.md)，沿用要求见[v0.2 基线](product/mentor-dialogue-and-debate.md)。[技术设计](architecture/mentor-dialogue-and-debate.md)仍需适配常驻群、跨次讨论和 AI 来源类型；产品需求确认不代表实现或部署完成。

**本轮已确认的首发范围（仅本群内容，`group_only`）**：用户同意先交付仅使用接管后该群真实接收到的本人输入、据此生成的本问题摘要和 AI 讨论产物的模式；不读取私人日记、长期记忆或私聊，不接受网页补充正文。原固定群通过核验后可接管为一个全新问题，保留旧档案但不复制旧问题内容、来源、摘要或 AI 结果。普通群消息由原日记导师主持并回应一次，只有本人明确请求全桌参考或辩论才组织多导师讨论。群成员或配置变化时暂停；本人重新核验通过后不自动调用模型，等待本人在群中继续。讨论总结通过原日记导师私聊预览并由本人明确确认后，保存到单独的“AI 导师讨论结果”区块，不自动写日记。既有携带个人来源的私人圆桌仍需更强的历史可见范围和事件连续性证明，保持待验收；本模式不将这两项能力标为已验证。实现边界见[仅使用本群内容的导师圆桌技术设计](architecture/group-only-mentor-roundtable.md)，本段记录已确认需求，不宣称生产现场验收成功。

- **单导师沟通**：每位导师有固定名称、头像和独立私聊入口；持续理解处境、澄清问题、适度挑战并提供建议，支持追问、另起问题和回看历史。
- **多导师参考**：由用户选择导师，先独立形成判断，再对比建议、依据、代价及适用条件。
- **多导师辩论**：在用户与受管导师组成的专属私人圆桌群中，由 Riji 主持，各导师以自身身份质询、回应和修订。用户可补充、提前总结或停止，最后得到有条件的建议、保留的分歧及可执行下一步。
- **常驻群与触发**：一个群固定一个长期问题，同题多次讨论复用群；普通本人消息由日记导师接话，明确请求多导师参考或辩论才组织全桌。新的一次讨论有自己的上限，重试或重启不清零同次用量。
- **讨论记忆**：完整档案、当前问题摘要、已授权长期记忆分层使用。新事实与纠正更新当前摘要，旧结论保留当时条件；重新分析可不沿用旧 AI 判断。圆桌不自动把建议、保存确认或计划捕获为已发生的用户事实。
- **共享与保存**：圆桌须核验群及全部成员，并单独授权本桌分享；不自动开放过去私聊、观察或候选，摘要继承来源限制。群内保存意图转到已验证的 Riji 私聊重新预览确认，不在群中创建或提交日记草稿。
- **独立 AI 结果**：日记单独显示“AI 导师讨论结果”，区分导师建议、用户明确采纳计划和实际反馈。内容性质贯穿预览、保存、切片、检索和导出，默认排除本人事实自动提取；只选择部分导师发言不缩小全群可见范围。
- **渠道与迁移**：导师、问题、记录和权限由产品自身持有；Feishu 为首个交付渠道，替换入口不应重建导师或重跑历史辩论。PRD 不固化框架、SDK 或调用参数。

新版建议固定群内保留原日记导师与四位导师，每次选择 2–4 位发言、默认最多 2 轮辩论；一个长期问题可先后进行多次讨论，同一时间最多一场。这些人数与轮数默认值可在试用中校准。普通群和未核验群继续无个人日记能力；确认成员或历史可见范围变化时停止新的个人内容发送，旧群不因成员恢复而自动继续，常驻复用不放宽这一例外。

本节定义下一阶段有界的私人圆桌例外；第 8 节及旧架构的“单 Bot、私聊限定”仍是新能力启用前的运行基线。旧 `/hermes/messages` 不通过伪装群为私聊获得能力，旧单 Bot 私聊保留兼容。功能按独立 Issue 实施，继承模型与来源权限、严格写入确认及 Air 部署边界；文档完成不授权建真实群、发布机器人或部署。
