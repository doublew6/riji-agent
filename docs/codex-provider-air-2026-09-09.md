# Codex 部署与验收

本文提供可复用的部署步骤、验收方法和代码验证记录。个人账号、主机身份细节、代理配置、真实来源范围、记忆计数、预算用量、备份标识和部署时间由维护者私下保管，不随仓库发布。

## 部署前提

遵循 [部署指南](deployment.md) 和 `AGENTS.md` 的 Air-only 边界。先核对授权的 SSH alias 与硬件身份，再在远端确认现有 runtime 和源码位置；不得猜测主机或从开发机 home 推断生产路径。

1. 完成本地代码回归、CLI 协议隔离及合成模型验证。
2. 在生产主机备份将被替换的文件及运行数据，校验 SQLite 完整性，分别记录 Mem0/PostgreSQL 与 history 的备份方式。应用层逻辑导出不能冒充 volume 物理备份。
3. 用精确清单 dry-run 同步，排除凭据、真实数据、数据库、日志、输出和缓存；不使用 `--delete`。
4. 在生产 runtime 验证同一发布测试清单、代码哈希与依赖。遗留目录测试与发布清单结果分别记录，不隐藏失败。
5. 核对端口归属、项目专属官方登录及合成联网调用。配置生效后运行 `doctor`，按既有服务命令管理已获授权的服务，检查 `/healthz` 和 loopback 监听。

## Codex 验证边界

导师与记忆 provider 可独立配置，详见 [接入说明](codex-provider.md)。官方登录仅存在于独立持久 `RIJI_CODEX_HOME`；不复制个人凭据或全局配置。服务重启不应要求主动退出登录。

每次 CLI 调用使用临时上下文；通用文件、Shell、浏览、skills、hooks、MCP 和 connector 工具必须实际禁用。已验证 CLI 版本为 `0.153.4` 与 `0.153.0-alpha.5`；未知版本关闭失败。Code Mode 禁用通知仅按精确已审计事件处理，不能为消除提示开放编码能力。

使用已有本机代理时，先验证部署进程的网络通路。`RIJI_CODEX_PROXY_URL` 只允许无认证信息的 HTTP(S) loopback 主机和显式端口，只影响 Codex 子进程；不得发布实际代理地址或把网络失败误判为凭据失效。

合成验收至少覆盖：普通导师回答、受限工具意图、结构化提取与来源引用校验。实际请求必须检查空通用工具集合与发送前权限 guard；收到候选不表示已经本地持久化，也不代表真实记忆质量。

## 固定历史批次与日常预算

```dotenv
RIJI_JOURNAL_MEMORY_DAILY_CHARS=100000
# Enable only for an explicitly authorized, fixed historical batch.
RIJI_JOURNAL_MEMORY_INITIALIZATION_UNLIMITED=false
```

开启例外需要用户明确授权。按 scan → grant → resume 顺序，冻结已授权历史 ID / 版本与当前有效版本的交集；空授权不能接纳后来出现的文件。后续扫描、授权或重试不扩充批次，新增或修改后的版本仍使用日常预算。

初始化请求通过 `initialization:UTC-day` 独立计量，旧日账本不清零、不追溯迁移。仅本批提取、关系判断及必要有界整理可以豁免日总量；单片段 900、同一来源版本累计 4000、private/local/none 和四种用途继续约束。提取与必要整理达到终态后持久关闭例外，不能因配置仍开启就重建无限批次。

本地 Review 应显示初始化模式和累计量、日常已用/上限、片段与来源限制、用途授权、当前接收方及授权 binding。恢复时区分待处理、成功、排除、重试与失败；`journal_incomplete_extraction` 表示模型输出不完整，不等价于日预算或账号额度不足。

## 运行验收记录要求

在本地私有记录中分别核对请求计量、来源版本和任务进度、已应用操作、Mem0 与快照，确认确实发生处理且没有重复写入。真实记忆条目数不等于已完成来源数；成功扫描、首条记忆落库、全量历史完成与质量合格是不同结论。

公开问题或报告使用合成样本和必要的脱敏错误类别。不得上传真实日记、记忆正文、用户标识、生产截图、账户用量、私人备份目录或完整运行日志。
