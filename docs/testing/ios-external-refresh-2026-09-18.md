# 外部文件刷新与冲突处理：2026-09-18

用户反馈：在手机 Obsidian 修改同一份 Markdown 后回到 Riji 继续编辑，会出现难以处理的冲突；电脑修改后也希望自动刷新。

## 已定位的问题

原文件保存采用协调访问和逐字节来源校验，不能通过关闭校验来修复。当前缺口在 App 的刷新流程：回来时只尝试刷新干净状态，忙碌或待保存时直接跳过；前台检查间隔为 60 秒；离开前台没有专门提交并保存原生正文/表格输入。正文撤销回原字节后，脏标记也未必消失。

因此，普通先后编辑可能继续使用过期的显示内容和保存依据。实际双方同时修改、未下载或权限失效、系统 iCloud 多版本冲突属于不同状态，需要分开处理。

## 验收目标

1. 离开 App 时提交并保留输入；回来检查当前原文件。前台持续检查晚到的更新，内容不变时不重置正文、光标、滚动和撤销。
2. 外部内容变化且没有本机差异时自动读取。异步检查过程中有新输入、切日或换目录时，过期结果不能覆盖当前页面。
3. 真实双方修改时显示清晰的比较与选择入口；采用最新文件、本机编辑或手动合并均重验来源，并保留双方修订。失败不丢稿。
4. 真正的系统 iCloud 多版本冲突单独提示，保留本机草稿导出和重试；不能把普通正文合并说成已经处理了系统版本。
