# 在 Mac 上手动验收 Riji iOS 本地工作流

当前语音实现仍在审查：256 项软件检查通过后，独立审查发现了[待修复的恢复问题与测试缺口](ios-voice-review-2026-09-13.md)。以下语音流程请使用合成测试内容；不能把本轮软件验证当作完整交付。统一的一键测试入口仍待实现。

本指南使用合成记录，检查已实现的离线原生功能。操作在 iOS Simulator 中进行，不代表已完成真实 iPhone、Air、生产后台、模型生成、账号、同步或录音验收。个人日模板已从现有 Obsidian 配置中定位，本轮已支持两种明确的格式化日期和标题行内样式；原模板尚未导入；周/月模板、指标和实际任务仍待定位。个人迁移需要原文预览、明确确认和单独逐字段核对。

## 启动 App，并保留验收记录

1. 安装完整 Xcode，并在 Xcode → Settings → Components 中安装 iOS Simulator runtime。在 Settings → Locations → Command Line Tools 中选择该 Xcode。
2. 双击仓库根目录的 **Run Riji Sample Simulator.command**。也可在 Terminal 的仓库目录执行 `./scripts/run_ios_simulator.sh --sample`。启动器构建 Debug 版本，并打开专用设备 **Riji Development iPhone**；不会抹除、卸载或重新创建已有设备。缺少工具、runtime 或出现重复设备名称时，应显示明确错误。如果同名旧设备因 runtime 缺失而不可用，应停止并提示恢复原 runtime，不创建另一个同名设备。首次创建设备时，只选与已安装 runtime 的最低、最高版本要求均相容的 iPhone 类型。
3. 确认启动后直接进入今天的日记，能看到 **产品初始模板** 和 **写一点…**，没有登录或连接设置前置流程。如需屏幕键盘，可在 Simulator 的 I/O → Keyboard 中关闭 Connect Hardware Keyboard。
4. 本指南所有输入只用合成内容。准备在输入过程中重启时，先等到 **草稿已保留在手机**，再双击 sample 启动器。重启后已落盘的草稿和已保存文件都应保留。
5. **Run Riji Simulator.command** 或 `--normal` 使用正常数据空间。sample 模式始终复用固定空间 `UITests-743D25D2-4E3E-4B8B-A8DC-70D8A4A59B12`。切换模式只重启 Riji App，不清除任一空间。自动化 UI 测试使用另外生成的 UUID，不重置这份手动验收空间。

## 通过 Simulator“文件”导入合成模板

Mac 仓库里的 fixture 路径**不在 Simulator 的“文件”中**。请先经系统保存选择器导出一份，再从同一位置导入：

1. 点日记页左上角的书本图标，进入日记目录 → **日 / 周 / 月模板**，保持选择 **日模板**。
2. 在 sample 模式点 **导出合成示例到文件**。在系统保存选择器中选择可写文件夹，保留文件名 `Riji-Synthetic-Template.md`，点 **保存**。记住所选文件夹；这份文件现在可由 Simulator 的“文件”访问。
3. 点 **从文件选择模板**，在同一文件夹或 **最近项目** 中找到刚保存的 `.md` 文件。**点文件缩略图打开，避免只点文件名区域。** 原文预览应显示 frontmatter 中的 `fixture: synthetic-manual-acceptance`、MIT/Evening/`🧠  **Notes**` 标题、`{{date:YYYY-MM-DD}}`、`{{date:dddd}}`、`{{weather}}` 和 `<% unsupported_synthetic_macro %>`。未知语法应有警告，并保持为原文。先取消一次：模板列表不应新增版本。
4. 再次选择该文件，点 **确认导入**。这一步才将原始 UTF-8 文件复制到 App 的 Templates 库中，导入本身不会自动选择它。打开新增的 **已导入日模板**，检查原文，再点 **使用此模板**。
5. 仓库中的同字节文件位于 `docs/testing/fixtures/riji-synthetic-daily-template.md`。也可把它的内容粘贴到模板编辑框，点 **预览粘贴的模板**，再点 **确认导入**。sample 模式的 **预览合成示例** 是进入相同预览与确认流程的快捷入口；它明确是合成验收数据，不代表已迁入个人模板。
6. 空文件、无效 UTF-8 或超过 256 KiB 的文件应被拒绝，当前模板选择应保持不变。App 不执行模板脚本，也不编造天气、健康等未知字段的值。

预期文件：`Documents/<namespace>/Templates/daily-<SHA256>.md`，字节应与导入源文件完全一致；内部状态另存已选择的模板 ID。重复导入相同内容不会新增第二个版本；导入内容恰好与产品初始模板相同时，列表也只显示一个相同内容的版本，但导入原字节仍保留。源文件不会被修改。若已确认的导入在落盘中途失败，重开相应模板列表或重新导入时会核对并恢复原事务；未确认的预览不会自动导入。

## 空白日记、记录、草稿模板绑定与搜索

1. 返回日记目录 → **保留空白日记**。选择一个验收日期，点 **预览空白日记**，核对日期、模板和完整预览，再点 **确认保留空白日记**。对同一天重复此流程，应只有一个文件，没有虚构的记录内容。
2. 关闭目录。所选日期应显示导入模板的标题和未解析宏。阅读标题应显示 **🧠  Notes**，隐藏样式分隔符；输入区默认目标仍保留原始 `🧠  **Notes**`。在该区块中输入 `Synthetic orchid observation`，点 **保存这段**，确认仍停留在原日期。关闭再打开 App：这段文字应保留且只出现一次。
3. 切到另一个日期，输入但不确认保存 `Synthetic pending text`。把已选择的日模板改回产品初始模板，再回到这份草稿：原文字、区块和原导入模板应仍然保留。保存应使用原有锚点，不能从新选模板重新构建旧草稿。已有日记没有已知模板来源时应显示中性的 **已保存日记 · 原模板保留**，不能因切换全局模板而把旧日记标成新模板。
4. 日记目录 → **搜索本地文件**，搜索 `orchid` 或已保存的日期。结果应包含类型、日期和片段。打开结果，检查已保存正文；点 **切换日记到此日期**，关闭目录后应能继续记录该日期。搜索 `Synthetic pending text`：未确认草稿不能作为已保存结果出现。
5. 已保存文字后，再对同一天执行保留空白日记，已有字节应完全不变。找不到目标标题或存在重复目标标题时，追加应被拒绝，输入保留。本次没有提供覆盖或任意编辑已有日记正文的入口。

预期文件：`Journals/YYYY-MM-DD.md`，内容为精确实例化的模板及本人明确确认的新增文字。草稿位于 Application Support，不作为已保存文件参与搜索。搜索只读取格式正确的日、周、月文件名；单次最多扫描 2,000 个文件、20 MiB 内容，并返回 100 条结果。结果按文件日期从新到旧排列（周报以周一、月报以首日为准），同日按日记、月报、周报稳定排列。超过 2 MiB 的文件会跳过，并显示跳过数量及部分结果，其余有效命中保留。达到扫描或结果上限时应有提示；更换搜索词不会缩小固定的扫描文件集合。

## 日期语言、标题样式与旧草稿

1. 模板页 → **日期偏好 → 星期语言** 应明确显示 **中文（星期一）**，可选 **English (Monday)**。选择 English 后重启 App、重开模板页，仍应显示 English。语言保存失败时应报告错误并保留先前设置。
2. 使用上述合成日模板，为 **2021-01-01** 预览空白日记：`date` 应是 `2021-01-01`（不能是周编号年份 2020），英文 weekday 应是 `Friday`；**2024-02-29** 应是 `Thursday`。改中文并为新日期预览，应显示对应的星期五、星期四。未支持的 `{{weather}}` 和脚本仍是原文。标题样式只影响阅读，模板原始文件和导出的 `## 🧠  **Notes**` 均保留双空格与星号。
3. 先准备空白日记预览，再返回模板页改语言或模板；重新进入仍显示的原候选应保留原预览。确认后导出 Markdown，比对 `date`、`weekday`、frontmatter、标题和未知宏，必须与所确认预览一致。若重新点 **预览空白日记**，则是明确准备新候选。
4. 为另一未保存日期输入 `Synthetic old draft {{date:dddd}}`，等草稿已保留；改语言并重启。原日期、文字和模板保持不变，文字中的 token 不应被重新解释。旧版本形成的普通/MIT/复盘草稿也不重渲染，原操作重试不会生成第二份结果。已有日记、已保存复盘不随偏好变动。
5. 粘贴合成模板 `## **🧠 Notes**` 与 `## 🧠 Notes` 两行，预览、确认导入并选择，再打开新日期。默认目标应是 **请选择写入区块**，保存禁用；明确选择唯一原始标题后才可保存。两个完全相同的原始 Notes 标题即使手选，保存仍应因歧义拒绝并保留输入。代码围栏和 HTML 注释中的标题不计为目的地。
6. 对周/月模板使用相同日期 token，新准备的复盘用周期起始日及当时已保存的星期语言。重开旧复盘草稿、重新核对来源并保留编辑，不能改变原文字。

补充检查：嵌套或未闭合的未知宏（含引号、行注释和块注释），以及 Dataview/DataviewJS 围栏正文都应保留原字节；围栏之外的受支持日期正常替换。H1 Notes 与其他 Notes 同时出现时，两者都应能明确选择。合法空标题显示为 **空标题**，不会与 **请选择写入区块** 混淆，草稿重启后仍可保存。带链接或图片的标题不因标签文字叫 Notes 就被归类为默认 Notes；原始标题仍可明确选择。

空白预览会直接说明剩余变量按字面保存。预览后若通过 MIT 等流程改变同一天的正文，原确认应报来源已变化、保留原候选；重新点预览并核对新正文后才能继续。星期设置即使连续遇到写入和回滚失败，也应保留原有效选择，重启与重试按内部恢复记录核对；设置损坏不应阻挡旧日记或已有草稿。

这些场景的磁盘写失败、旧 JSON 缺字段编码/哈希、事务/回执恢复和 CRLF 字节检查由 Core/State 自动测试覆盖；手工操作不修改真实运维数据。

## 北极星 → MIT → 实际反馈

1. 日记目录 → **北极星指标**。填写合成的指标名称、口径、单位、目标、周期和当前阶段，当前测量留空。点 **预览北极星版本**，逐项核对后点 **确认北极星版本**。当前测量应显示 **尚未记录**，不能显示 `0`。
2. 新增第二项指标。对第一项点 **修改为新版本**，修改目标并确认。两项当前指标都应保留，展开历史应能看到第一项的旧目标与旧版本。填写测量值却不注明来源及截止时间时，应拒绝保存，并保留可见输入。测量值和来源说明也各受 8,000 字节的输入上限约束，拒绝无效输入后旧指标仍应可读。
3. 返回一个验收日期 → 日记目录 → **最重要的一件事**。选择一项北极星，或明确保留 **未关联 · 手动计划**。输入 `Synthetic practice task`、可验证完成标准、原因及可选的建议投入。选择真实存在的 MIT 标题；产品初始模板或自定义模板没有 MIT 专属标题时，请明确选择一个现有区块。刚在模板页切换选择后，可以直接从目录进入 MIT；区块应来自该日期的实际日记或其已绑定草稿，无需先返回今天页刷新。
4. 点 **预览 MIT 记录**，核对日期、目标区块、行动和完成标准，再点 **确认写入当天日记**。应产生一个当前 MIT。重启后再次进入，仍应是同一项已确认计划；确认计划不能被标为已经完成。
5. 输入不同计划并确认更换预览。应仍只有一个当前 MIT，旧计划保留在历史及 Markdown 中。开启 **记录实际反馈**，先保持 **请选择** 并填写结果进行预览、确认，保存应被拒绝，不能默认判为部分完成。再明确选择 **部分完成**，填写具体实际结果和原因，选择反馈区块，预览并确认。再分别选择 **完成** 和 **未做** 做一次合成验收。每次反馈都应是单独确认的历史记录，不自动把计划顺延到明天。
6. 在确认 MIT 预览之前修改它引用的北极星版本，旧预览应失效。错误应保留表单字段；点 **核对最新来源并保留输入** 后应重新载入目标及当前 MIT。原指标关联和文字保留；若指标已被新版替代，先明确选择一个有效版本，再预览确认，不能自动改目标或解除关联。若当前 MIT 已被另一项已确认计划替换，刷新后新预览应基于最新计划说明更换关系，保留本人输入。若事务已落盘但保存结果尚不确定，应保持原候选供重试，不能以编辑产生新操作替代原确认。

预期文件：`Goals/<version-UUID>.md` 为带确认日期、不可变的指标版本。MIT 采纳、更换及反馈会在所选日记区块追加可读的带日期 Markdown，并保留稳定 ID 和来源注释。当前计划从更换关系中确定；旧正文不被覆盖。

## 周报与月报：手动编辑、确认和回看

1. 日记目录 → **周报 / 月报**，默认选中上一 ISO 周。点 **打开周期复盘**，核对周一至周日的起止日期、固定日记时区、可用日记来源及全部缺失日期。点一条日记来源，应能看到实际已保存内容。
2. 改选当前周，应显示 **进行中** 及截止日期；选择尚未开始的周或月，应显示 **尚未开始**，不能标为历史周期。选择没有日记的周期，应如实提示并允许手动填写，不生成经历或指标数值。跨年核对例：2021-01-01 所属周应为 2020-12-28 至 2021-01-03。
3. 编辑手动复盘，等到 **复盘草稿已保留在手机**，关闭并重开 App，再打开同一周期。编辑文字和来源哈希应保留。如出现输入未保存错误，重新打开周期时应先重试最新输入；重试仍失败应保留可见编辑和错误，不能用较旧的落盘草稿替换。北极星和 MIT 表单也遵循此规则。不要在尚未落盘时强制结束 App。点 **预览确认复盘**，核对完整文字及周报目标，再点 **确认保存复盘**。
4. 再次打开已保存周期，应先展示已有报告。点 **追加新的复盘版本** 才进入新修订流程。确认后，第一份报告及其来源链接应保留在文件开头。**打开并导出已保存复盘** 应使用系统 Markdown 导出选择器。
5. 切到 **月报**，默认日期应改为上一个自然月。选择 2024 年 2 月，应包含 29 天，结束于 2 月 29 日。每日来源 ID 只出现一次。本次离线实现直接使用每日证据，已有周报不增加重复计数；缺失的测量值保持缺失。
6. 检查来源失效：保留一份复盘草稿，返回其某篇来源日记，追加并确认一段文字，再打开或确认旧复盘。旧预览应被拒绝，编辑文字应保留。点 **重新核对来源（保留编辑）** 更新哈希，再核对并确认。若原保存结果尚不确定，编辑器应保持原确认文字供重试。
7. 导入带 YAML frontmatter 的周模板，并创建一份此前未保存的周报。模板最前面的 `---` 应仍在文件的第 0 字节，来源说明位于手动模板正文之后。日、周、月模板的选择相互独立。
8. 异步操作期间使用系统返回，再进入另一表单：新页面应等原操作结束后加载自己的输入，不能沿用上一页的字段或把新增输入写到上一表单。取消进入某页不应在稍后把当前页面切成该页的表单。

预期文件：`Weekly/<Monday-YYYY-MM-DD>.md` 和 `Monthly/<first-day-YYYY-MM-DD>.md`，复盘不能写入 Journals。文件应保留手动作者性质、准确周期、截止日期与时区、模板版本、每日来源 ID/哈希、缺失日期及全部已确认修订。内部复盘草稿和回执不会作为单独文件导出。

## 只检查合成验收空间

启动 sample 模式后，可用以下命令取得已安装 App 的数据目录：

```sh
xcrun simctl get_app_container 'Riji Development iPhone' com.riji.local data
```

在命令返回的目录中，只检查这两处：

- `Documents/UITests-743D25D2-4E3E-4B8B-A8DC-70D8A4A59B12/`
- `Library/Application Support/UITests-743D25D2-4E3E-4B8B-A8DC-70D8A4A59B12/Riji/`

安装过程中 CoreSimulator 的 container UUID 可能变化，不要把返回的完整路径写死。正常模式直接使用 Documents，以及 `Library/Application Support/Riji`。

文件替换遵循“刷盘 → 原子重命名 → 目录刷盘”，已确认工作流保留持久化事务与回执。写入、替换、回执和清理等故障边界由 Swift 测试注入验证，不应通过损坏用户 Mac 存储来手工制造故障。真实磁盘耗尽、锁屏/后台时序、VoiceOver、大字体及实体 iPhone 仍需另做设备验收。

## 合成 WAV：文件、回放、校正、插入与普通保存

使用 **Run Riji Sample Simulator.command** 和已有 `Riji Development iPhone`，不抹除或卸载 App。以下步骤不点今日日记麦克风或 **开始录音**，不会采集环境声音。

1. 在一个合成日期与唯一的原始区块中输入 `Existing before voice`，等草稿已保留；选择 **更多 → 恢复的录音 → 新建待整理记录**。页头应显示原日期、原区块，此整理入口不得申请麦克风或 Speech 权限。今日日记麦克风属于另一个显式的一次点击录音动作，自动文件验收不要使用它。
2. 向下滚动到 **合成音频验收**，点 **导出合成 WAV**，在系统“文件”选择器保存。随后点 **从文件导入测试 WAV**，从该选择器选回同一个文件。不要填写 Mac 仓库绝对路径。
3. 应出现一个约 1 秒的可用片段。点 **回放第 1 段**，应实际播放合成纯音，并显示核验后的时长。应在实际结束后显示回放完成；播放期间可点 **停止回放**，解码失败不得继续显示成功。纯音回放成功不能标为中文识别成功。
4. 在 **校正文字** 输入 `Exact synthetic voice correction`。点 **预览插入**，核对文字及 `../Attachments/Audio/<recording>/<segment>.wav` 相对链接；点 **确认插入输入区**。回原日记页，旧输入完整保留，校正原文与链接只追加一次。此时尚未正式写入日记。
5. 点普通 **保存这段**。关闭并重新打开 App，原日期、保存后的正文、音频和校正应仍保留。通过更多 → **恢复的录音** 重开该录音，不得申请权限或自动开始录音。已插入录音应显示明确说明，校正、转写和再次插入不可用；**新建录音** 应绑定当前日记并允许新的输入，不自动开麦。每段 **导出原音频** 应与第一步合成 WAV 字节一致；Markdown 导出应仅含正式保存的文字与原相对链接。
6. 导出取消或失败时原音频和文字应仍保留。选择 **删除原音频 → 确认只删除原音频** 后，回放/继续/旧媒体预览不得再可用，校正文字及已经保存的正文与链接保持原样；删除失败显示已申请、移除待核验，不能仅因 tombstone 就声称音频消失；可重试原件移除。不能把该操作描述为删除已导出的副本或系统备份。
7. 暂停录音后准备插入预览，再明确继续录音时，旧预览应消失，不能在录音/等待权限时用旧确认插入。文字校正后也需新预览。另一普通保存改变同一天来源时，旧插入须拒绝；使用 **核对当前正文并刷新插入来源**，核对实际正文和新预览后才能继续，原日期与 raw heading 不变。

已有的未完成或损坏末段应保留，带“可能无法播放”的说明仍可 **导出原音频**；启动失败只预留了片段时可能没有音频文件，必须如实显示未核验并给出导出失败，不能声称原件存在。正在录制的段、符号链接、被替换的已完成音频或已申请删除的原件不能导出。只有损坏状态记录的录音库也应在库中显示不可读数量/错误与重试入口，不误报为空。

在受控 State 测试中验证多段中文转写的第一段成功、第二段失败/取消和重启：第一段成功结果必须保留，重试只识别缺失段，最后按原音频顺序形成一份原稿。校正文字不被这些回调覆盖；该端口验证不代表 Simulator 或真机已成功识别中文。

音频在合成 namespace 的 `Attachments/Audio/` 中；manifest、校正、原始转写与插入意图在相同 namespace 的 Application Support/Riji 中。导出各段后保持原段文件名与相对目录布局，可连同 Markdown 一起带走。本次尚未提供整个日记库的打包恢复。

Core/State 自动测试用临时合成文件及受控硬件端口覆盖权限拒绝/迟到、分段轮换、启动落盘时的中断、旧 callback、录音保留失败、损坏末段、媒体变化、转写候选与人工校正隔离、删除 tombstone、跨日/namespace、插入 draft afterReplace 及回执清理后的幂等恢复。它们不启动真实麦克风，也不模拟一份成功的物理设备验收结果。
