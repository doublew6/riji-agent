# iOS 本地手动验收

2026-09-18：本页描述当前已实现版本的操作，不能视为已完成新版个人 MVP。[PRD v3.0](../PRD.md)的首个导航增量已实现右滑前一天／左滑后一天、日记／导师／记忆／设置四个并列底部入口。已授权原目录中的日记正文已接通协调原位编辑；已有单导师私聊与逐条记忆接入，圆桌和结构化记忆概览待独立 PRD 评审。合成 fixture 验证客户端流程，真实手机与 Air 服务的验收须分别记录；后续目标见[个人 MVP 验收清单](ios-personal-mvp-acceptance.md)。

日记页按 2026-09-14 的反馈调整为直接编辑正文。本文用于电脑上的 iOS Simulator 检查；真机中文转写、后台录音、Air、账号同步和 AI 功能需要各自验收。语音仍有[已记录的审查问题](ios-voice-review-2026-09-13.md)，语音检查请使用合成内容。

## 打开 App

- 日常使用：双击仓库根目录的 **Run Riji Simulator.command**。普通使用空间保留个人配置与日记。
- 合成测试：双击 **Run Riji Sample Simulator.command**。该入口使用独立、固定的示例空间；其中的产品或合成模板不代表个人模板。
- **个人模板检查和最终交接使用普通入口。** 合成测试结束后重新运行 `Run Riji Simulator.command` 回到个人空间；不要把仍处于样例空间的内置模板当作个人模板的展示结果。
- 两个入口使用同一个 Riji App 和既有专用模拟器。不要卸载 App 或抹掉模拟器来切换模式。
- 显示屏幕键盘：在 Simulator 的 **I/O → Keyboard** 关闭 **Connect Hardware Keyboard**。
- 模拟手机滑动：把指针放在正文，按住鼠标左键或按下触控板不松手，再拖动。查看后面的内容要把正文向上拖；在页首向下拖只会回弹。普通触控板滚动不能当作手机触摸滑动的验收依据，操作映射见 [Apple 的模拟器手势说明](https://developer.apple.com/library/archive/documentation/IDEs/Conceptual/iOS_Simulator_Guide/InteractingwithiOSandwatchOS/InteractingwithiOSandwatchOS.html)。需要快速去最后一段时，点击键盘上方的 **文末**。

## 本地文件树

设置路径：直接点击首页底部第四项 **设置**，与 **日记、导师、记忆** 并列。日记目录内不再显示独立的设置栏。

1. 点今日日记左上角的目录图标。已连接本地文件夹时，首先看到真实的根目录和子文件夹；当前 Mac 验收连接已有 `riji` 目录，真机通过 **打开文件夹** 在系统“文件”中选择。
2. 点击目录左侧箭头展开、再点折叠；检查 `daily`、`templates`、`weekly` 等层级与原目录一致，没有复制成一份新的目录结构。只读取当前展开层。
3. 打开已授权原目录中能唯一识别日期的 daily 日记（含嵌套路径），进入同一日记正文编辑器；直接输入、修改或撤销会保存回该原文件。templates、weekly、monthly、非日期 Markdown 和其他 UTF-8 文本仍使用标注 **只读** 的一般文件预览，不显示编辑键盘，也不写回原库；关闭后回到文件树。PDF、图片和常见音视频调用系统本地预览，使用选中文件的临时副本。
4. 关闭并重开 App，所选文件夹应恢复。点 **打开文件夹** 后取消，原连接和文件树应保留。
5. 用 **刷新文件树** 重新读取目录；文件被其他程序移动/删除时显示错误，可重试或重新选择，不自动创建替代文件夹。隐藏文件、符号链接和特殊文件不作为可编辑内容开放。
6. 原有模板、MIT、周/月复盘、搜索和 App 已保存日期在 **App 日记与工具**；未连接外部文件夹时，这些入口仍在目录页显示。**打开今天** 返回原有日记编辑页。

当前日记主页使用已授权的原 daily 文件，首次编辑缺失日期时才按原模板建文件。一般文件预览继续只读。正常阅读和自动保存时，底部不再出现“已保存在此设备”框、禁用麦克风和常驻 iCloud 说明；保存状态保留无障碍读出，错误及恢复操作仍就地出现。录音入口在“更多”，历史日期的“回到今天”在顶部；iCloud 同步说明保留在设置，本机保存不意味着电脑与实体 iPhone 已完成传播。文本预览上限 2 MiB，其他支持的预览上限 32 MiB；不支持的类型或超限会说明原因。真机的系统目录授权、撤销授权及第三方文件提供方仍需实机验收。

## 本次导航增量：Mac 上检查六项

以下检查使用示例空间和合成文字，不修改个人原件，也不请求麦克风权限。

1. 打开一篇较长的合成日记，收起键盘并取消选字。在普通正文处按住鼠标从左向右拖动约半屏，检查打开前一个日历日；再从右向左拖动回到原日，并继续到后一天。检查 2025-01-01 ↔ 2024-12-31、2024-03-01 ↔ 2024-02-29，再点 **回到今天**。未来及缺失日应显示原模板预览，不自动创建文件，也不跳到最近已有文件。
2. 在同一正文分别向上、短距离向左／向右及明显斜向拖动；日期保持不变。点正文编辑、中文组合输入、选字或拖动光标时，两个方向均不切日。在含 `|` 的表格行开始拖动时不切日；宽表格左右横滚仍应停留当前日记，纵向拖动滚动正文。
3. 在长文中间放置光标，收起键盘，再滚到另一段；记住所在段落。右滑前一天再左滑回原日、从目录打开原日期、切到导师再回日记，均应恢复该日期的阅读位置和光标，正文逐字保持。首次打开新日期从顶部开始，不能用撤销带回另一日期的编辑。位置只保证当前会话，重启后不作承诺。
4. 点击首页底部第四项 **设置**，确认与日记、导师、记忆并列，根页没有多余返回按钮；打开模板与星期语言、Air 状态子页后可返回设置。没有递归的“更多”。切回日记，内容与阅读位置保留。日记目录不另有设置栏；展开长文件树、打开文件预览再关闭，原树展开与滚动位置保持。原模板、MIT、复盘、搜索和导出入口仍能找到。
5. 查看底部 **导师**、**记忆**：未激活的示例空间应如实显示 **服务尚未激活**；连接 fixture 可检查单导师私聊与逐条记忆，但不能据此声称真实 Air 已验收。返回 **日记** 可继续本地记录。设置说明原日记正文自动保存在原文件，并区分本机保存和 iCloud 传播；其他文件预览保持只读。
6. 查看自动测试的合成故障证据：保存失败后双向滑动、点导师、记忆或设置均留在原日记，最新文字及重试入口保留；未解决的冲突或“稍后处理”的合并也阻止这些动作。不要通过填满磁盘或损坏个人文件手工造故障。原来的只读恢复查看、导出与显式日期浏览继续可用。

1. 打开后直接看到今天的日记正文。顶部有目录、日期和更多；正文下方没有另一个输入框、写入区块选择或“保存这段”。

3. 长按选择句子中间的 `morning`，改为 `evening`。检查修改发生在原处，前后文字和模板栏目保留；光标没有跳到文末。
4. 在别的段落中间继续输入，测试换行、中文输入和撤销。收起键盘后仍在同一天、同一篇文档。
5. 等保存完成后关闭、重开 App。修改后的内容应仍在原位置，不能另追加一份原文。
6. 切到另一个验收日期再回来，核对内容。跨午夜保留当前正在编辑的日期；切到新一天是明确动作。
7. 在示例日记中留下未闭合的 Markdown 代码围栏或列表，保存并重开。写到一半的文档仍应可编辑，不因缺少可解析标题而丢稿。

## Markdown 实时预览

在合成测试空间检查以下行为，普通空间只阅读已有日记即可：

1. 打开日记且不弹键盘时，标题不露出 `#`，粗体不露出 `**`，列表显示圆点，空列表也显示圆点，任务显示空框或勾选框，`---` 显示分隔线。
2. 点击普通正文行：这一行暂时显示 Markdown 标记供原位编辑，其他行继续排版。点击另一行或 **收起键盘**，原来的标记自动收起；不另开编辑框。表格使用下面的单元格编辑流程，不切回整段管道符源码。
3. 在示例正文写下 `**粗体**`、`*斜体*`、`~~删除线~~`、行内代码和 `- [ ] 示例任务`。换行、移动光标和收起键盘，确认相应样式出现。点击任务框后等待保存，检查勾选状态；用键盘工具栏撤销、重做，确认原文字仍在。
4. 修改粗体中的中文，输入法候选阶段不能被排版打断。选中多行、替换、撤销、切换日期再回来，核对正文和位置。
5. 保存后重开，再通过 **导出 Markdown** 核对原始标记、链接目标和换行都在。页面隐藏的符号不会从文件中删除。
6. 当前支持常见标题、粗体/斜体、删除线、行内代码、简单列表/任务、分隔线、引用及普通链接/双链标签。标准表格的交互见下文；复杂嵌套、插件及未完成语法尚未全部支持，附件预览和链接跳转以具体入口为准。代码围栏、缩进代码、未知模板表达式和受保护属性保留原文，不执行脚本或下载内容。

## 表格单元格编辑

在合成测试空间准备一份带有表头和数据行的 Markdown 表格，更新后的构建按以下步骤验收。自动验证结果与实体 iPhone 待检查项见[本次表格改动记录](ios-inline-tables-2026-09-18.md)。

1. 点击有文字的单元格，输入或修改文字：键盘出现，当前格内出现光标，整个表格仍保持网格。空白格也应能直接输入。当前格内的行内 Markdown 标记可以用于编辑，整张表不切成源码。
2. 在数据行按回车：当前行下方多一行，光标进入新行的同一列；在表头按回车则在表头分隔行后新增第一行数据。原行内容不被截断或覆盖。
3. 点击表格底部加号追加末行；点击右侧加号追加末列。宽表左右拖动可看到右侧内容，纵向拖动仍滚动日记，两个动作都不切换日期。
4. 输入中文候选、表情、竖线和反斜杠，再收起键盘或切换底部设置后返回，核对文字与网格。中文候选期间保存回调、宽度变化不应让光标或输入框消失。
5. 使用撤销、重做分别检查单元格修改、新增行、新增列。关闭、重开 App 后结构和文字仍在；导出 Markdown 核对表格前后的正文、未知属性、原对齐及换行没有被重新排版。
6. 故障与只读恢复由合成自动测试检查：输入保留，失败提示和重试入口仍有效；只读状态不能借助表格控件改写原文件。不要通过破坏个人文件制造故障。

## 原模板与新日期

已授权原目录模式直接使用原 templates/daily.md 与原日期规则准备新日期，浏览不建文件。下列导入、语言与空白页步骤针对仍保留的 App 本地日记空间；该空间使用其已导入模板副本。切换来源不会迁移旧日记或自动化，也不改变原周/月模板。

在示例空间检查通用导入：

1. 目录 → **日 / 周 / 月模板** → **日模板**。使用 **导出合成示例到文件**，将示例保存到系统“文件”。
2. 点 **从文件选择模板**，点刚保存文件的缩略图。预览应保留 frontmatter、MIT、带样式的 Notes、格式化日期和未知表达式。先取消一次，列表不应新增版本。
3. 再次选择文件并 **确认导入**，打开新增版本、点 **使用此模板**。导入和选用是两个独立动作。
4. 打开尚未创建的日期，检查采用该模板；日期按日记时区实例化。未支持的天气表达式和脚本原样保留，不填虚构值或执行脚本。
5. 在新文档中直接编辑，再更换全局模板。已经写过的日记不能重套新模板。原来未完成的旧追加草稿也保留其模板和文字。
6. 在 **日期偏好 → 星期语言** 切换中文/English，为新的验收日期准备页面。检查 2021-01-01、2024-02-29 等边界；旧日记和已准备候选不应随偏好改动。
7. 目录 → **保留空白日记** 可显式建立历史空白页；同日已有文件先打开，不重复套模板。

模板原始文件必须与导入源文件逐字节一致。合成样本位于 [riji-synthetic-daily-template.md](fixtures/riji-synthetic-daily-template.md)。空文件、无效 UTF-8、超过 256 KiB 的导入被拒绝；原选择保持不变。

## 搜索与导出

1. 目录 → **搜索本地文件**，搜索已保存的合成句子。打开命中后应进入对应日期。
2. 搜索不会把未落盘编辑或内部恢复记录当作正式日记。返回结果有明确范围，未找到不表示这件事从未发生。
3. 更多 → **导出 Markdown**。保存到系统“文件”，用电脑查看内容：正文修改、未知属性、原始链接和模板结构均保留，内部回执不进入导出。
4. 再导出一次并取消，原文应保持。没有已保存内容时，不能声称已导出完整日记。

## 修订、失败与旧草稿

只在合成空间进行故障检查，不修改个人原件或用填满电脑磁盘的方式测试。

- 在 Riji 打开已保存的测试日记，切到手机 Obsidian 修改并保存同一文件，再回 Riji：应自动显示最新文字，继续输入后能正常保存。连续往返两次，不能因仍持有旧正文而报冲突。
- 保持 Riji 前台，用 Mac 修改同一测试文件；待 iCloud 把新版本送达手机后，Riji 应自动刷新。Mac 保存到手机收到的时间属于 iCloud 传播，不把 Riji 的前台检查间隔当作跨设备同步时限。
- 没有文件变化时连续输入、选字、撤销或编辑表格，后台检查不能把光标/页面移回顶部。中文候选未确认时也不能被刷新覆盖；离开 App 后回来，已输入内容应保留。
- 如果 Riji 中的改动已全部撤销回原文，之后收到外部更新应能正常加载，不能仅因曾输入过文字而判定双方修改。
- 正文修订和修改前内容保存在本机内部恢复记录中，当前尚无独立的历史版本浏览页；自动测试会核对修订内容，界面可在冲突时比较双方。
- 保存失败时，页面应保留最新文字并显示尚未保存，重试成功后才显示完成。失败不能通过切换日期悄悄丢掉编辑。
- 原文件或整个目录暂不可用时，最新文字仍保留在本机来源绑定草稿中；冷启动显示“本机恢复草稿”，可选字复制或用 **导出本机草稿** 导出，不冒充已保存的原文件。重新选择同一原目录可更新授权再重试；选另一目录不能消耗旧草稿，也不能重建已删除原文件。
- 双方确有未合并修改时，应能查看当前文件版和本机编辑，并选择 **使用文件最新版本**、**保留本机编辑** 或手动合并；明确选择后再次核对文件版本，双方旧内容保留在修订中。不能用一个迟到的自动保存覆盖另一份新内容，也不能只反复提供“重试保存”或“重新选择目录”。
- 实际 iCloud 多版本冲突应走独立的系统版本处理入口；普通正文合并不能冒充已解决系统版本冲突。按下节检查，不主动制造私人日记的云端冲突。
- 编辑冲突合并稿后先选“稍后处理”，再次打开应保留合并中的文字；确认前仍可核对双方来源。
- 合并文字尚未成功保留时，切换日期或打开其他工作页应停在当前文档，保留最新文字与重试入口。保存进行中，合并和旧草稿的输入控件应明确暂不可编辑；失败后恢复。
- 在合成模板上尝试改动受保护的属性或来源标记：应给出简短提示，原文和保存状态保持；改写普通正文仍可正常完成，提示随后清除；切换日期也不带走旧提示。
- 恢复记录异常的注入由自动测试执行。预期界面仍显示完好的已保存正文，并明确处于只读恢复状态；导出只包含这份已保存内容，不能声称未恢复的修改也已导出。原异常记录保留。
- 在正文改名或移除原来的语音目标标题后，语音入口应提供可见的目标恢复选择；不能一直报错而没有处理入口。
- 若打开以前的未保存追加草稿，使用出现的恢复入口检查文字，明确采用后才写入正文。打开页面本身不会自动提交旧草稿。
- 文件替换前后失败、未知结果重试、来源碰撞等确定性故障主要由临时合成库自动测试验证；不要把普通关闭/重开当作全部故障路径已验收。

## 系统 iCloud 版本冲突

以下是 2026-09-19 修复的验收步骤；具体执行结果见本轮测试记录。自动测试使用合成版本提供器，不把它当作真实云端传播证明。

1. 从日期选择器或原目录打开有系统冲突的日记。即使没有本机草稿，也应显示当天可读取的正文及 **查看并处理版本**，正文暂时只读。
2. 进入处理页，默认按章节仅看差异，确认相同段落折叠；表格改动带表头显示。逐处保留、采用另一版或只编辑该片段；切换比较版本、稍后处理和重开后，已合并内容应保留。“完整原文与导出”仍可展开全部内容，包括文档属性。若某版本尚未读取成功，仍能阅读、导出其他版本，并重试；不能直接确认舍弃未读版本。
3. 先写一段手动合并内容，再选择稍后处理并重开；合并文字应保留。也可导出单个版本，在其他编辑器核对。
4. 在合成数据中确认当前版、其他版或合并稿；最终页面优先显示相对当前原文件的实际变化，并保留完整结果入口。重开检查所选内容完全一致，未选择的段落、换行与 Unicode 字节不变，处理前的版本和拟保存结果仍能恢复、导出。原有本机未保存草稿不得因系统冲突处理而被自动提交或删除。
5. 用自动化注入核对：预览后出现新版本、当前文件再次变化、备份失败、写入后中断和部分版本标记失败。旧确认不能覆盖后来的修改；失败必须留下重试或重新核对入口。
6. 真机只检查已经存在且已备份的冲突，或本人指定的专用测试文件。记录手机系统版本、操作、处理结果和另一设备收到的内容；不得用模拟器通过或 App 安装成功替代这一步。

## 北极星与每日 MIT

1. 目录 → **北极星指标**，使用合成目标填写名称、定义、单位、目标周期和阶段。测量值有值时注明依据和截止时间；没有依据保持为空。
2. 预览并确认，重开核对。修改定义应生成新版本；历史记录保留原版本。
3. 目录 → **最重要的一件事**，选择已保存指标或明确的手动计划，填写一个行动、完成标准和原因。预览、确认后回正文检查实际写入。
4. 更换 MIT 后只有一个当前计划，旧项仍在历史。记录完成、部分完成或未做时必须明确选择状态并填写实际反馈；没有反馈不默认当作完成。
5. 本地界面当前支持手动定义与计划，不把它表述为 AI 已根据真实北极星自动生成。
6. 在正文原位置修改刚确认的 MIT 行动或完成标准，再打开 MIT 页面：应明确显示正文已修改、原确认记录待核对，不能将旧字段当作一致的当前计划直接填完成反馈。通过手动计划预览并确认新版，检查新计划成为唯一当前项，旧文字与确认历史仍保留。
7. 在其他日记段落补一句话，不改变 MIT 本身：当前计划不应被误判为冲突。
8. 修改正文里一条旧反馈的可见文字，再看计划与反馈历史：应标明该原确认记录与正文有差异，不能静默把旧完成状态当成修改后的结果。已有的完整新计划不应仅因旧历史有差异而失效。

## 周报与月报

1. 目录 → **周报 / 月报**，查看上一完整周或月；检查起止日期、已保存来源、缺失日期和截止时间。
2. 当前周期显示进行中，无资料时明确缺口；不能生成虚构经历或填零。
3. 手动填写复盘，预览确认。保存到 Weekly/Monthly 对应类型，不能混入每日目录。
4. 重开先看到已有报告；修改产生新版本并保留旧内容。来源日记改动后重新核对依据。
5. 检查跨月周、跨年 ISO 周和 2024 年 2 月。原周/月模板、模型生成和既有自动任务尚未完成迁移时，以实际状态为准。

## 合成语音与正文衔接

使用示例空间和生成的 WAV 验收文件流程；自动检查不打开麦克风。

1. 先在正文保存 `Existing before voice`。更多 → **录音记录**，建立一条待整理记录。
2. 在合成音频验收区域导出一秒测试 WAV，通过系统“文件”重新导入。回放应能完成，回放完毕不会一直显示播放中。
3. 输入合成校正文字，打开插入预览，检查实际日期、目的地、文字和相对音频链接。
4. 确认后回日记，文字应进入正文，不再要求回到底部框点一次“保存这段”。原录音和校正版本保留。
5. 等本机保存完成后重开，同一录音不能再重复插入。分别导出 Markdown 和原 WAV，确认正文、相对链接和原音频字节。
6. 保存或插入结果未知时先核对同一操作，不能通过重建录音或重新点击造成重复。暂不采用时保留原音频和校正。

真实麦克风、中文离线识别、长录音、电话/锁屏/后台/路由变化、耗电与发热仍需实体 iPhone 单独验收。上述合成音频不能证明语音识别准确性。更详细的旧版语音故障场景保存在[此前追加界面的验收基线](ios-manual-acceptance-append-baseline.md)，其中旧输入框的操作已由本指南取代。
