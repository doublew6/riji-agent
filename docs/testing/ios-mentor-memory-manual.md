# 圆桌与结构化记忆：电脑和手机验收

本清单对应已确认的 [圆桌 PRD](../product/PRD-ios-roundtable.md) 和 [结构化记忆 PRD](../product/PRD-ios-memory-overview.md)。列出的行为是验收目标，不是完成记录；已执行的检查和发布状态见[集成验证记录](ios-mentor-memory-2026-09-20.md)。

## 电脑端先体验

在项目根目录双击以下文件，会编译当前代码并打开已有的 `Riji Development iPhone`：

- [Run Riji Memory Demo.command](../../Run%20Riji%20Memory%20Demo.command)：进入“记忆”检查主题、摘要、依据和纠正。
- [Run Riji Roundtable Demo.command](../../Run%20Riji%20Roundtable%20Demo.command)：进入“导师 → 圆桌”检查对话和保存结果。
- [Run Riji Simulator.command](../../Run%20Riji%20Simulator.command)：切回正常模式，保留此前的正常日记与配置。

也可在项目目录的终端执行：

```sh
./scripts/run_ios_simulator.sh --memory-overview
./scripts/run_ios_simulator.sh --roundtable
./scripts/run_ios_simulator.sh --normal
```

一次运行一个入口。编译期间等待终端显示打开成功；失败会保留已有 App 数据并显示具体原因。两个功能演示和原有 sample 模式各用独立、固定的合成数据目录；重复启动保留该目录的本机草稿。正常启动会清除继承的测试开关。不会创建一批同名模拟器，也不卸载 App 或抹除模拟器。

两个功能演示入口只使用 Debug 合成服务，不连接 Air、不调用真实模型、不读取手机文件。记忆演示的服务响应每次启动恢复为合成场景，不能用它证明生产记忆已修改；来源变化、撤权和持续历史另有 API/State 自动化回归。模拟器的飞行模式也不能模拟合成传输断网，断网与未知回执按自动化用例验证。不要在演示中选择真实日记目录。

正常模式使用已保存的目录和独立设备授权，可以读取真实日记并连接真实服务。2026-10-14 已恢复 `Riji Development iPhone`（iOS 26.5）的原目录连接，并验证真实服务授权与记忆读取，见[恢复记录](ios-simulator-real-data-2026-10-14.md)。日常体验使用这个设备；`Riji Automated Tests`（iOS 27.0）用于自动化。模拟器不会自动复制手机的聊天记录。正常模式下编辑原目录会修改实际 Markdown 文件；Mac 上的目录访问不代表真机 iCloud 已通过验收。

滑动时，把指针放在模拟手机的内容区域，按住触控板或鼠标左键后拖动：向上拖看下方内容，向下拖回到上方。日记切换日期时先收起键盘，在普通正文区域横向拖动，右滑前一天、左滑后一天。参见 [Apple 模拟器手势说明](https://developer.apple.com/library/archive/documentation/IDEs/Conceptual/iOS_Simulator_Guide/InteractingwithiOSandwatchOS/InteractingwithiOSandwatchOS.html)。

### 圆桌

1. 打开“导师”，顶部应有“圆桌 / 先和主持人聊聊”。点入后能直接输入，无需先填写标题或背景。
2. 输入一个合成问题，例如“本周只有两小时，怎样安排学习和复盘”。第一次发送应只出现主持人回复。
3. 写一半下一条消息，关闭并重新打开 App；返回同一聊天，确认草稿和已接收消息仍在。
4. 点击邀请，选择两位导师和参考模式；核对本次选中的聊天材料。界面应说明主持人和四位固定导师的可见范围。
5. 确认后观察发言者、等待和完成状态。过程中补充“实际只有一小时”；旧条件下尚未交付的答案不能混入新结论。
6. 测试停止、部分总结和继续；停止确认后不应继续出现新的有效发言。未知请求应提供核对方式，不能靠反复发送解决。
7. 修改当前条件，确认旧结论保留历史背景并标为需重评。再从菜单另开一个不相关聊天，原聊天应在历史中保留。
8. 选中一个 AI 结果，预览日期和独立 AI 区域后保存到合成日记。再次确认或冷启动恢复都只写入一次；保留 AI 来源，不能变成已经执行的个人事实。
9. 保存预览打开时，从另一编辑器修改目标文件。确认应提示文件变化、保留预览；刷新并重新核对后才写入。

### 结构化记忆

1. 打开“记忆”，首先看到生活主题和有证据的摘要，而非一长串原始记录。空主题应如实说明，不能补写画像。
2. 从主题进入一条认识，再看支持依据；从首页到依据不超过三次点击。计划、历史阶段与待验证观察应容易区分。
3. 打开“导师观察”，检查所属导师、支持记录、反例和限制。单个导师的观察不能显示成全体共同确认的事实。
4. 在摘要中进入“这条认识不准确”，选择原始依据进行纠正。提交前有修改核对；成功后旧摘要立即失效，失败则保留输入。
5. 打开待复核项，对照双方依据。不得自动删除或合并；原始条目的搜索、复核和归档仍可使用。
6. 请求整理，确认显示真实任务状态和覆盖范围；打开页面本身不能启动新的 AI 请求，停止的历史批次不能被此操作重开。

## 断线和版本检查

断网后先确认未发草稿仍可编辑；已下载内容标明时间和离线状态。重连时核对原请求回执，不应重复创建讨论或整理任务。服务器已明确告知撤权、来源变化或账号切换后，不得回退展示旧缓存中的失效内容。

列表分页过程中若数据版本变化，应重新载入同一版本；加载失败不能显示为“没有记录”。旧服务尚不支持新接口时，页面应明确说明，并保留已有单导师聊天和原始记忆入口。

## 真机最终验收

本地自动化通过后，分别记录 Air 服务版本、安装的 App 构建和真机操作结果。真实 Air 先使用合成问题验证一轮主持人及圆桌回复；真实日记写入由本人在预览后确认。确认手机蜂窝网络可直接使用已配置的服务，四个主标签仍为日记、导师、记忆、设置。

自动化通过、生产服务更新、手机安装和本人体验确认是四项独立证据，不互相替代。
