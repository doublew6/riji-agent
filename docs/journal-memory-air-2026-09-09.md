# 日记长期记忆部署检查

本文是通用部署与验收方法。真实日记来源范围、文件数量、记忆计数、数据库规模、用户配置和备份标识保存在私人运维记录中，不作为公开示例。

## 准备与发布

按 `AGENTS.md` 验证 Air 主机身份，确认现有源码镜像、生产 runtime、服务与端口归属。开发机仅编辑和做无副作用验证；不得用开发机生产 Compose 代替目标主机验收。

- 同步前备份即将替换的文件和相关运行数据，并验证 SQLite、PostgreSQL、Mem0 history 的恢复范围。
- 使用经过核对的文件清单 dry-run 后同步；排除 `.env`、数据库、日志和生成物，不使用 `--delete`。
- API 镜像只更新本项目授权范围内的服务；不重启共享 Colima、其他项目容器或已知异常挂载容器。
- 在生产 Python 上执行发布清单测试，随后验证 API 健康、本地向量模型及 Review；使用同一 production executable 执行 `doctor` 和服务管理。

## 初始化与来源权限

先保持处理暂停，扫描已授权日记目录和区块，核对实际接收方、日期范围、private/local/none 排除与预算。取得绑定当前配置的授权后再恢复处理；扫描本身不调用模型。

日常预算默认每 UTC 日100000字符；单片段900、同一来源版本累计4000字符。用户可显式授权一次固定历史批次的每日总量例外，独立计量且自动结束；具体状态机见 [日记长期记忆](journal-memory.md#本次历史初始化的例外) 和 [PRD](PRD.md#166-用户确认的预算调整2026-09-09)。

分别记录来源状态、提取进度、真实持久化、失败和预算等待。不能用文件扫描数推断全部历史已经提取，也不能把合成模型候选当作个人记忆成果。

## 已记录的开发验证

开发阶段本地回归及发布清单曾各通过504项检查。对生产镜像全部遗留测试的独立运行包含508 passed、12 failed，相关 media/Web 测试不属于当时发布清单；不能把此结果写成全目录通过。

合成验证覆盖 Mem0 幂等管理操作、本地 embedding、来源/权限过滤及真实 Review 路由。特定用户的日记质量、飞书实发实收、长期增量和备份恢复仍须在对应部署中单独核验。
