# Riji 视觉设计规范

**方向：暖光书桌 · 沉静深绿。** 温馨、现代、安静，以奶油纸底和低饱和深绿构成主要印象；通过清楚的排版、精确对齐、少量等宽数字和来源标注，表达轻微的极客与科技感。

文档类型为 **Visual Design Guidelines（视觉设计规范）**，包含可复用的 **Design Tokens（设计变量）** 和组件规则，是 Riji 设计系统的视觉基础。本文用于任何新页面、改版和设计评审，不依赖某一份页面示意图，也不代表组件库已全部实现。

主稿保存在维护者的 PRD 文档目录，仓库同版副本为 `docs/DESIGN.md`；两处同步维护版本与正文，不各自发展成不同规范。仓库内的新页面任务通过 `PROJECT_GUIDE.md` 进入本文。

| 奶油纸底、低饱和沉静深绿、现代无衬线字体 | 已确认；本轮最终浅色配色见第 3 节 |

之前展示的十页设计仅用于探索风格，不作为所有页面的最终方案。本文不收录整套页面截图、固定的主题分类或示例流程；后续任务不需要复制样稿中的卡片数量、标题文案、目录结构或控件位置。

## 2. 设计语言

### 2.1 温馨来自色温与阅读节奏

- 大面积使用奶油纸底；需要承托重点内容时，使用燕麦色的暖层。
- 圆角柔和，段落有呼吸感，正文适合持续阅读和书写。
- 保持平整、干净的数字界面；不添加纸张噪点、仿旧纹理、厚重书本投影或装饰性插画。
- 温和文案应帮助理解；无需给每个页面增加问候语、口号或抒情标题。

### 2.2 现代感来自无衬线字体与层级

- 中文使用苹方或平台系统无衬线字体；英文使用 SF Pro 或平台系统无衬线字体。
- 标题靠适度字重、字号和留白区分，正文自然、清晰，不做复古书刊排版。
- 不使用宋体、衬线体、书法体或手写体作为产品界面字体。
- 每个视图有清楚的主内容和主操作，辅助信息退到次一级。

### 2.3 轻科技感来自准确的细节

- 日期、时间、简短编号和来源索引可少量使用等宽数字或 SF Mono。
- 用一致的对齐、细分隔线、轻量图标和可追溯的来源关系表达秩序。
- `[01]`、日期编号等只在帮助定位时出现，不为制造科技感给所有栏目加编号。
- 不加入霓虹色、发光描边、全屏网格、无意义终端字符、技术状态仪表盘或装饰性数据。
- 用户需要首先感到这是自己的记录空间，细看时再发现数字工具的精致。

## 3. 已确认的浅色配色

所有色值为 sRGB HEX。实现时使用语义变量，不在各页面另选一组近似色。

| 变量 | 色值 | 名称 | 用途 |
| --- | --- | --- | --- |
| `color.paper` | `#FAF4EA` | 奶油纸 | 页面与主要阅读区域背景 |
| `color.warmSurface` | `#F0E3D2` | 燕麦暖层 | 重点内容、输入承托和少量分组背景 |
| `color.selectedSurface` | `#E7EBE2` | 灰绿浅层 | 选中态、轻量强调、关联信息承托 |
| `color.brand` | `#2D5342` | 松柏深绿 | 品牌、当前导航、可操作的重点标签 |
| `color.action` | `#355C4B` | 柔和深绿 | 主要按钮、确认动作与选中控件 |
| `color.forestSurface` | `#253D32` | 墨绿 | 少量需要更强识别的入口或重点区域 |
| `color.text` | `#30372F` | 深灰绿 | 正文、标题、主要信息 |
| `color.textSecondary` | `#676554` | 暖灰 | 辅助说明、时间、次要信息 |
| `color.border` | `#D9D7C7` | 暖灰分隔 | 轻分隔、输入边界、必要的结构线 |
| `color.onAction` | `#FFF9F0` | 按钮暖白 | `color.action` 或 `color.brand` 实底上的文字与图标 |
| `color.onForest` | `#FAF4EA` | 墨绿面主文字 | `color.forestSurface` 上的主信息 |
| `color.onForestSecondary` | `#CCDCCD` | 墨绿面辅助文字 | `color.forestSurface` 上的次要信息 |

### 3.1 使用规则

1. 奶油纸底占据主要阅读面积；绿色集中表达选择、操作和少量重点。
2. 正文使用 `color.text`，不将整篇正文或所有标题染成绿色。
3. 常规重点内容优先使用暖层或灰绿浅层。墨绿实底只用于确有层级需要的少数区域，不连续铺满多个模块。
4. 品牌绿、操作绿、墨绿按角色使用；不要为了让按钮突出，单独提高饱和度。
5. 同一个组件跨页面保持配色一致。不同主题、导师或栏目不各自发明一套鲜艳色系。
6. 输入控件、分隔和辅助文字都保持温暖色调，避免重新引入冷蓝灰的界面骨架。

### 3.2 明确淘汰的配色方向

最初的星巴克绿色仅是寻找色相的参考。用户随后明确要求降低饱和度、加深绿色、减少刺眼感，因此不再使用早期的 `#006241`、`#00754A` 作为本产品品牌与操作默认值，也不回到高饱和亮绿、荧光绿或通用系统蓝的整套界面主题。

本版以本节的低饱和色值为准，不重新从外部品牌页面取色。系统自带选择器、键盘等原生系统表面遵循平台行为，无需强制改色。

## 4. 字体与排版

### 4.1 字体分工

| 场景 | 选择 | 规则 |
| --- | --- | --- |
| 中文标题、正文、控件 | 苹方 / 平台系统无衬线 | 使用平台动态字号能力，避免捆绑远程字体 |
| 英文与一般数字 | SF Pro / 系统无衬线 | 与中文保持一致的视觉密度 |
| 少量醒目的日期数字 | SF Rounded / 系统圆润无衬线数字 | 可以保留 A1 的亲近感，不要求每个页面都有大日期 |
| 时间、来源索引、短编号 | SF Mono / 系统等宽字体 | 只用于元信息；中文段落和按钮标签不采用等宽字体 |

iOS 优先使用系统字体 API；网页可使用 `-apple-system, BlinkMacSystemFont, "PingFang SC", sans-serif`。字体缺失时回退到无衬线字体，不回退到宋体或其他衬线体。

### 4.2 实现默认值

以下是复现风格的起点，不是锁死的物理尺寸。原生使用逻辑 pt，网页使用 CSS px；随系统文字大小、屏幕和内容长度调整。

| 层级 | 默认参考 | 字重 |
| --- | --- | --- |
| 页面标题 | 28 | Semibold / 600 |
| 重要内容标题 | 20 | Semibold / 600 |
| 列表标题 | 16–17 | Medium / 500 或 Semibold / 600 |
| 连续阅读正文 | 16–17 | Regular / 400 |
| 辅助说明 | 12–14 | Regular / 400 |
| 短编号、时间等元信息 | 11–12 | Regular / 400；不能承载唯一的关键提示 |
| 可选的大日期 | 40–52 | Medium / 500；仅在确有日期层级需要时使用 |

中文正文行高以约 1.7–1.9 倍为参考；长文不挤压行距，按钮和列表按各自内容密度处理。层级同时依靠字重、颜色和间距，不只通过不断放大标题实现。

## 5. 空间、形状与层次

- **间距节奏：** 常规采用 4、8、12、16、20、24、32 的刻度；相关内容靠近，不同语义组留出更明显距离。
- **页边距：** 手机以 20–24 为起点；被选样稿为 22。长文、窄屏和大字号优先保证可读宽度。
- **内部留白：** 内容容器以 16–20 为起点；段落和语义组之间通常为 20–28。
- **圆角：** 内容容器默认 18，主按钮 14，次按钮与输入框 10–12，小标签 6–8。嵌套时协调内外圆角，不给所有元素同一个大圆角。
- **层次：** 以表面色差为主，用细线辅助；常规内容不加明显投影，不叠多层卡片。
- **边界：** 分隔线只帮助定位。避免将每个段落、标签、行都装进带边框的盒子。
- **密度：** 写作与阅读区舒展，目录和工具区可更紧凑；不要求所有页面使用相同卡片布局。

设计稿中的手机外框、状态栏、底部手势条、固定画板高度属于展示环境，不是待实现的产品组件。不得把画板尺寸写进实际页面布局。

## 6. 可复用的组件语言

| 组件 | 通用表达 |
| --- | --- |
| 主按钮 | 柔和深绿实底、暖白文字；一个局部决策区有明确主操作；默认高度约 46，文字变化时可扩展 |
| 次按钮 | 纸底或透明背景、深绿文字、必要时暖灰细边；强调弱于主按钮 |
| 文本入口 | 深绿文字，配简洁图标或方向提示；不把重要操作藏在纯图标中 |
| 导航选中态 | 灰绿浅底配深绿图标和标签，也可用字重或短标记辅助；不只依靠颜色区分 |
| 内容承托 | 少量暖层或灰绿浅层；连续正文优先自然排版，避免逐段卡片化 |
| 输入区域 | 暖层或纸底、明确但轻的边界、清晰光标和聚焦反馈；不以深色大框压过内容 |
| 来源与依据 | 紧凑日期/编号、可读标签、细线建立关系；展开后保持与正文一致的阅读质量 |
| 标签 | 小面积低对比底色、清晰文字；只标明实际类型、状态或范围 |
| 图标 | iOS 沿用 SF Symbols；网页使用风格一致的线性图标；权重与文字匹配 |

不将 Emoji 作为产品导航或通用装饰体系；用户日记正文、原模板已有的 Emoji 和图片按内容原样保留。头像与品牌图形可单独设计，不能把样稿中的单字占位头像当作已确认最终资产。

## 7. 交互、状态与可读性

这些规则约束表达质量，不增加页面功能或变更业务流程。

- 控件有可区分的默认、按下、选中、禁用和聚焦状态；网页适配悬停与键盘焦点，触屏不依赖悬停。
- 触控目标以至少 44 × 44 为设计基线；视觉图标可以更小，点击区域不相互覆盖。
- 轻反馈可采用约 100–180 ms，展开与切换约 180–240 ms；优先平台原生动效，尊重减少动态效果设置。
- 避免持续闪烁、呼吸光效和无意义动画；高频输入、保存和阅读保持安静。
- 普通文字与实际背景的对比度以至少 4.5:1 为验收目标；重点检查浅色承托上的辅助文字和实底按钮上的文字。
- 设计稿的颜色组合计算不能代替真机、浏览器、深色模式、大字号和 VoiceOver 等实际验收。
- 事实、观察、AI 建议、待确认、失败和过期状态需要文字说明，不能只用绿色或图标表达。
- 绿色表示品牌或交互不等于业务成功；成功反馈必须来自真实结果。
- 不为营造科技感在主界面展示内部 ID、模型调度术语或无意义计数。

## 9. 新页面执行与评审

设计新页面时依次完成：

1. 读取本文，确认使用的是 1.0 或后续明确更新的版本。
2. 读取对应页面最新需求，确定用户任务、主内容、主操作及真实状态。
3. 先应用字体、颜色与层级，再根据内容选择连续正文、列表或必要的内容承托。
4. 优先复用现有组件；原生和网页分别采用适合平台的导航、输入和可访问性机制。
5. 在正常、长内容、无数据、错误、较大字号等相关状态下检查；采用深色模式时另行核验。
6. 记录相对本规范的必要偏离及原因；常规页面布局变化不需要重新确认整套视觉风格。

快速检查：

- 第一印象是否温馨、安静，正文是否仍是主角？
- 是否使用本版低饱和绿色，而非早期亮绿？
- 中文和标题是否为现代无衬线字体？
- 等宽字、编号和细线是否帮助理解，而非堆砌技术感？
- 是否出现过多绿色实底、重阴影、卡片套卡片或装饰边框？
- 控件、辅助文字和状态是否可读、可点、可理解？
- 是否误把旧页面示意当作最新功能或布局要求？
