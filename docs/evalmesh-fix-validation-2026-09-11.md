## 复验方法

继续使用固定 EvalMesh 源码、独立合成 vault/SQLite 和 LocalChannel。记忆模型请求为
`deepseek-chat`，导师与检索为 `deepseek-v4-pro`。每个批次单独封存源码、用例、依赖与
评审判据，运行前后核验完整性；目标输入不含期望答案。尝试数与字符数不是费用。

原 12 题 smoke 每题重复三次，其中 4 题使用受控故障/渠道，8 题调用真实模型。
另设 4 组固定首轮观点，每组三次，单独检查主持人对互补建议、真正二选一冲突、
少数反对意见和带条件的优先级取舍的比较。后者最多 12 次请求、不修复重试，
只验证比较阶段，不作为新端到端场景加入原 120 题分母。

逐字证据只能验证归因，不证明语义相斥。内容评审单独检查实际观点、条件、正文与
结构字段是否一致，以及计划和事实是否混淆。评审由助手完成，不是独立人类盲测，
也不代替用户帮助感、手机阅读或实际飞书体验验收。

## 结果

原 smoke 的三次重复没有达到放行门槛，后续修复使用新批次验证，不覆盖其失败。

| --- | --- |
| #44–#47 整合后的全量测试 | 1611 通过、5 跳过，0 失败 |
| 40 题受控边界复验 | 40/40，无真实模型调用 |
| 原 smoke 三次重复，C | **30/36**；12 个受控尝试全部通过，真实模型 **18/24** 通过；10/12 个场景三次均通过 |
| 比较语义对照，C | 4 组 × 3 次，**12/12** 结构及核心内容判据通过；仅比较阶段 |
| #48 初次整合全量测试，D | 1631 通过、5 跳过，0 失败 |
| 40 题受控边界复验，D | 40/40；相同场景的重复覆盖 |
| 两道检索题各三次，D | **6/6** 机器通过，六次均修正了搜索缺口表述；另发现一处相对日期/事件锚点错误 |
| 明确正文引文规则后的全量测试，E | **1637 通过、5 跳过，0 失败** |
| 实际失败输入的比较阶段重放，E | **3/3** 严格引文及全部结果契约通过，无修复重试；核心无分歧判断有依据，局部表述仍可更精确 |
| 两道圆桌题单次端到端复验，E | **1/2**；无分歧讨论四次请求、零修复并完成综合；计划题第二位导师请求传输失败，不作三次稳定性结论 |
| 最后日期说明补充的定向测试，F | 原有 20 项证据边界测试通过；未新增测试，属于重复覆盖 |
| 受影响检索题三次复验，F | **3/3** 机器及目标内容判据通过；绝对日期、查询锚点和事件日期区分正确，未再写错相对日数 |

5 项跳过为四项需要显式指定官方 Codex executable 的离线 wire/schema 检查，以及一项
需要显式指定浏览器 runtime 的可选 UI 检查。跳过不能算通过。

**C 的六次圆桌失败全部保留。** 五次以 `model_transport_failed` 中断；一次比较输出
把同一导师的 `next_steps` 摘要当成 `text` 正文引文，一次修复后仍被拒绝，最终为
`invalid_generation`。另一个尝试先改写了引句标点，修复请求随后发生传输中断。
这些失败没有生成或投递替代主持人内容；尚未完成的比较、综合和计划续聊不能评为通过。
五次传输中断已有可用分类，但无法仅凭该分类判断远端或网络的具体成因。

正文引文补丁明确 `quote` 的唯一字段来源、连续子串、标点和空格约束；错误时要求按
发言 ID 从 `text` 重新选择。没有把摘要字段纳入可接受正文，没有提高重试次数。
E 的三次阶段重放使用 C 实际失败时的相同输入观点，重新生成输出；没有把旧回答
修改成合法答案。E 的两道端到端题另用全新场景状态，分别只运行一次。

私聊原题三次均能继承首轮具体处境，并按最新许可切换到小建议；教练题三次均维持
45 分钟录音草稿的范围。记忆单条经历与重复事实关系两题三次均通过内容检查，未将
输入 `observed_at` 混入候选字段。检索 D 的六次均不再把未搜到当作没有记录；其中
一条却误写相对天数并把查询锚点当会议日期，因此 F 补充日期证据说明并另行复测。
F 的三次均符合该目标判据；D 的原错误未被删除。

助手评审仍记录了少量推断或归因措辞过满。上述“核心判据通过”不表示每句话完全
无瑕疵，不包含用户帮助度，也不构成一般场景质量放行。
