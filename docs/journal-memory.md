# 日记长期记忆操作说明

本功能对应 [Issue #40](https://github.com/doublew6/riji-agent/issues/40) 及专项 PRD 的日记、隐私和 Codex 增量。日记仍在 Obsidian 编写，飞书仍先预览草稿、确认后追加；后台从授权区块形成记忆。免费使用本地存储、管理、导出和恢复，模型费用或套餐用量由用户自己的配置决定。

实现与测试状态见 [验收记录](journal-memory-acceptance.md)，技术分工见 [架构设计](architecture/journal-memory.md)，部署方法见 [验收说明](codex-provider-air-2026-09-09.md)。日常预算为 100000 字符；用户可显式授权一次固定历史批次不设每日总量上限。真实运行状态由本地 Review 与私有运维记录核验，不能用文档示例代替。

## 启用范围

沿用 `RIJI_JOURNAL_ROOT`，只扫描其 `daily`、`weekly`、`monthly` 子目录中的 Markdown，支持多年嵌套目录。外部对话文件不在本次发现范围内。既有原生对话捕获保留，`memory backfill` 仍只用于项目自己的历史聊天。

在运行主机的本地配置中设置：

```dotenv
RIJI_MEMORY_PROVIDER=mem0
RIJI_JOURNAL_MEMORY_ENABLED=true
RIJI_JOURNAL_MEMORY_USER_ID=ou_replace_with_allowed_owner
RIJI_JOURNAL_MEMORY_SECTIONS=🧠 Notes
```

用户 ID 必须属于 `RIJI_ALLOWED_FEISHU_USER_IDS`。区块清单以逗号分隔，匹配 Markdown 标题及其下级标题；标题的加粗标记和连续空格按等价文本处理，来源保留原始标题。不要把示例中的用户 ID 原样使用。可通过 `RIJI_JOURNAL_MEMORY_DATE_FROM`、`RIJI_JOURNAL_MEMORY_DATE_TO` 设置包含端点的日期范围。不配置日期时保留日期未知的来源；配置日期范围后，日期未知的文件会排除并显示原因。

新功能默认关闭。已有派生记忆时关闭提取，读路径仍保留来源检查，不因关闭功能而把旧来源限制绕开。一个日记运行库只绑定一个用户；更换归属需新建运行库并走显式恢复流程。

日记文件的原文、模板、标题和目录不会被提取器写回。`private: true`、隐藏文件、模板、附件、符号链接、代码块及命中凭据模式的片段均排除。凭据过滤是保守的模式识别，不能代替把敏感材料移出授权区块。

## 历史初始化与增量

以下命令使用部署环境中既有的 `riji-agent` executable。生产只在 Air 运行；开发机验证应使用隔离的合成目录和配置。

```sh
riji-agent memory journal plan
riji-agent memory journal initialize --max-jobs 100
riji-agent memory journal status
riji-agent memory journal pause
riji-agent memory journal resume
riji-agent memory journal retry
riji-agent memory journal run --max-jobs 100
```

`plan` 只扫描本地文件并建立持久清单，不调用模型。`initialize` / `run` 每次最多处理指定数量的片段，不保证一次处理完所有文件；输出中的 `initialized`、文件状态和预算才是完成依据。后台服务启用后会启动补扫、定期发现并继续处理。暂停阻止新的模型调用与写入；已经出发的请求无法撤回，但返回结果会重新检查暂停与权限状态。

Memory Review 的“暂停自动处理 / 继续自动处理”控制日记提取与整理的长期自动开关，不表示历史任务正在运行。顶部单独展示固定批次的历史片段覆盖、整理失败及待处理 / 恢复数量；历史片段全部完成后，仍可按增量授权处理新增和修改。整理失败且没有恢复任务时明确提示不会自动重试；后台整理等待日常额度时单独提示，避免与历史覆盖混淆。来源提取结束不能当作整理全部成功。

后台默认每 60 秒补扫；修改时间不足 2 秒的文件暂记为不稳定，下一轮再读取。默认文件最大 256 KiB、每次读取等待最多 2 秒，临时不可读的 iCloud 文件保留失败原因并继续补扫。处理水位不以日记日期判断，因此新放入的旧日记、停机期间的编辑、改名和删除均能被发现。改名按新路径发现，旧依据退出，相关检索及去重再关联；不承诺跟踪文件系统 inode 作为永久身份。

`retry` 重新开放失败任务和来源预算任务，保留已完成提取缓存，不能清空累计预算。模型返回格式错误、截断、引用不存在或越界目标时不形成有效记忆。任务默认最多尝试 3 次；超过后需要重试操作。调用结果不确定时，按持久操作 ID 查询，避免重复写入。

## 预算与覆盖

| 配置 / 限制 | 默认值 | 统计方式 |
| --- | --- | --- |
| `RIJI_JOURNAL_MEMORY_SEGMENT_CHARS` | 900 | 每个授权原文片段，最大允许 2000 |
| `RIJI_JOURNAL_MEMORY_SOURCE_CHARS` | 4000 | 同一文件版本累计发送的原文字符；关系判断重复携带该片段也计入 |
| `RIJI_JOURNAL_MEMORY_DAILY_CHARS` | 100000 | 日常增量提取、关系判断及常规日记整理的全部请求正文字符，含提示词和已有事实；按 UTC 日累计 |
| `RIJI_JOURNAL_MEMORY_INITIALIZATION_UNLIMITED` | `false`；本次按授权设为 `true` | 显式开启一次固定历史批次的每日总量豁免，独立计量；不取消 900 / 4000 字符限制，批次结束持久关闭 |
| `RIJI_JOURNAL_MEMORY_SCAN_SECONDS` | 60 | 扫描周期，最低 5 秒 |
| 新旧关系检索 | 每个候选最多 8 个近邻 | 合并后最多 12 个旧事实，语义相似只用于找候选 |
| 主动整理 | 每轮最多 5 个种子 | 每种子带最多 12 条相关事实、4500 字符事实正文 |
| 回答上下文 | 默认 2000 字符 | 含事实标签、有效时间与来源引用，观察最多 2 条 |

日常预算按 UTC 日期累计，超过 100000 字符后次日继续；来源预算按文件版本累计，初始化也不能绕过。不是 token 数或价格估算，也不是整个产品所有模型调用的总预算：原生对话和检索工具保留各自既有边界。调用前记录阶段、来源 ID / 版本和字符量；不在出云审计中复制请求正文。

### 本次历史初始化的例外

用户于 2026-09-09 明确要求本次历史初始化不设每日总量限制。显式开启初始化例外后，先扫描，再保存绑定新预算的历史授权，最后恢复。固定清单只取已授权证据 ID / 版本与当前有效版本的交集；未扫描或授权名单为空时保持 `awaiting_scan`，空授权后出现的新文件不能自动成为历史。后续授权、扫描和重试不扩充已冻结批次。之后新增的文件、后来补入的旧日期日记或编辑后的新版本仍是增量，使用每日 100000 字符额度；不能因为日期早或初始化还在运行而自动豁免。

初始化提取、关系判断及以本批产出记忆为种子的必要有界整理，按 `initialization:UTC-day` 单独累计请求字符，不占日常额度。普通种子的整理不能借用初始化身份。Review 显著展示日常已用 / 上限、初始化累计、批次状态及完成/未完成数量；状态接口的 `initialization` 对象提供 `enabled/state/active/total/pending/completed/excluded/failed/organization/request_chars`。其中 `request_chars` 汇总本批各日用量，`organization` 分列必要整理状态。状态接口还提供 `recovery_pending/recovery_spent/recovery_active/exemption_active`，分别说明当前适用初始化账本的待发送恢复、已发送待结果恢复、有限恢复预算是否仍有效，以及原批次或有限恢复是否仍适用例外。预算状态不代替用途授权和暂停控制。单片段 900 字符、来源版本累计 4000 字符、private/local/none 排除、四种用途和发送前校验保持不变。

新策略生效后，应立即恢复本批次中仅因旧 `daily_budget` 等待的任务，保留缓存、幂等操作和历史审计，不顺便重跑旧失败。来源累计预算不得清零；模型账号额度、认证和网络仍按原规则退避。提取达到终态且必要整理完成后持久关闭豁免，即使开关仍为 `true` 也不自动重开。暂停和撤回仍阻止相应调用，重启恢复原批次，不能留下永久无限处理开关。

批次及必要整理均达到终态时，无失败记为 `completed`，有失败记为 `blocked`；两者均不再无限处理。`blocked` 需要查看失败原因，不能将其当成全部成功或自动创建新批次重跑。

用户于 2026-09-10 进一步确认，本固定批次按失败 ID / 版本显式登记的一次整理恢复也使用初始化账本，不设每日总量上限。该规则取代之前把这些恢复计入日常额度的规则；配置仍须启用、当前范围须匹配冻结批次，且保留原种子首次发送记录。原批次即使已为 `blocked`，也可单独显示有限恢复额度有效，不把整个初始化重新设为 `active`。仅因日常额度等待的有效恢复可继续；发送后的恢复不再领取，成功、失败或排除后保持终态。普通整理、新增文件及修改版本仍按日常预算处理。页面区分总恢复队列和适用初始化账本的待发送 / 已发送待结果数量；范围不匹配、配置关闭、批次取消或恢复终结时不显示有效豁免。

调整预算时保留旧日账本，不清零、不追溯转移到初始化账本。生效时点、队列恢复及真实使用量在本地独立核验并私下保存，不能把配置示例当作运行状态已经改变。

Review 的“日记来源”展示所选根目录、日期和区块、来源分母、完成 / 待处理 / 失败 / 排除 / 删除、没有可记内容和预算等待。分母是扫描器在上述三类目录发现并检查的文件，不包含被提前跳过的隐藏目录与符号链接。表格最多展示 200 行，可按相对路径筛选；CLI 状态保留完整清单。记忆条数不等于已读文件数，索引完成不等于记忆初始化完成。

## 提取、更新与主动整理

模型从单个授权片段生成内容、类型、明确自述 / 推断、有效日期及原文引用。程序验证引用属于该片段，日期未知时不编造。旧记忆只用于判断关系，不能伪装成本次来源提供了某个旧细节。

提取输入中的 `observed_at`、来源 `kind` 和 `section` 是来源元数据。每条候选必须且只能返回 `content`、`kind`、`certainty`、`valid_from`、`quotes` 五个字段；事实时间未知时 `valid_from` 保持 `null`，不能仅因原记录有日期就补成事实日期。支持原生结构化输出的 provider 继续接收业务 JSON Schema；其他 provider 在同一次请求的 system 消息中接收同一 schema，并将其计入发送字符预算。这是模型提示约束，不表示服务端提供 schema 强制校验。

本地严格校验仍拒绝额外字段、无效日期、伪造引用和越界关系目标，不自动删字段、修补结果或追加模型请求。发送前的来源 / 目标权限校验与预算检查仍生效；已有任务重试规则见上文，输出契约不新增重试或 provider 回退。

同义重复增加依据；补充保留原事实并关联新的细节；状态变化按事实生效时间保留当前和历史阶段；时间不足、同时矛盾或涉及人工修订时保留冲突，等待查看。两次相似经历仍可分别保留。模型不能直接删除记录、修改其他用户 / 导师的记录或静默覆盖人工修订。

每次来源或事实变化触发整理请求。worker 在原生聊天捕获、日记处理和整理之间轮转；整理通过相关检索跨越历史处理批次，不只比较同一批。至少两个独立、明确的日记经历才可归纳观察；同一事实的聊天、日记及周月汇总不增加独立次数。同日事件保守视作同一次经历，日期未知和仅汇总证据不用于证明模式。

观察包含支持、反例和限制，以“待验证观察”进入回答。来源或事实变更后先停用旧观察，后台重新整理。检索只覆盖有界近邻，因此不能承诺发现全库所有反例。模型选择是否遗漏某个反例仍需要真实模型评测。

CLI 初始化只处理日记事实；跨批次观察由后台 worker 的整理任务产生。管理页也可请求“整理现有记忆”。未运行后台 worker 时，不能把 CLI 成功理解为整理已完成。

## 查看、纠正与遗忘

使用既有本地入口 `/admin/memory`，登录令牌不进入 URL。新增来源进度和操作按钮；事实详情展示类型、阶段、生效时间、来源段落及版本、关系目标和判断依据。归档退出召回，可手动恢复。`MEMORY.md` 是只读快照，显示阶段与时间；通过 Review 修改事实。

“选择遗忘范围”先列出当前事实、关联事实和来源片段，由用户勾选并确认。默认只选当前条目；选择片段会同时列明并删除其派生记忆，阻止同一片段再次提取。程序重新核对计划版本与用户权限，不让模型猜测“忘掉这件事”的范围。

删除先保存最小 ID / 内容指纹 / 段落指纹抑制，然后清理活动记忆、对应 Mem0 history、审计前后正文、派生报告和快照。后端不可用时立即停止召回，显示待清理并后台重试。原始日记保留；删除不抹除用户自行保管的旧备份，也不是磁盘取证意义的物理擦除。

对事实正文做人工纠正，会建立独立的本人修订依据；之后删除原日记不撤销这次人工确认。另有有效原生聊天依据时，删除日记来源也不会把真实存在的聊天依据一并否定。

## 导出与恢复

Review 可下载结构化 JSON，或执行：

```sh
riji-agent memory journal export --output /absolute/local/backup/journal-memory.json
riji-agent memory journal restore --input /absolute/local/backup/journal-memory.json
riji-agent memory journal restore --input /absolute/local/backup/journal-memory.json --apply
```

路径必须在日记根目录之外；文件权限为 0600，最大 32 MiB。导出包括事实、归档状态、证据关系、人工修订、来源范围、遗忘指纹和预算，剔除原文片段、提取缓存与任务令牌。服务端完整导出上限 100000 条；超过时明确失败，不提供冒充完整的前 N 条备份。

恢复默认仅验证。`--apply` 只允许空目标记忆库，或同一备份的中断恢复；先备份运行 SQLite、暂停处理、重放当前与备份中的遗忘规则，再写入并映射新的记忆 ID。恢复后重新检查本机授权和源文件，保持暂停，检查完成后再 `resume`。备份中的范围只用于核对，不自动扩大目标环境授权。没有原日记时，日记派生事实不会凭备份绕过来源校验；人工修订或独立聊天依据按各自规则保留。

JSON 不包含原始日记、完整编辑历史或全部运行审计。灾难恢复仍需用户分别备份日记、PostgreSQL、Mem0 history volume、`journal-memory.sqlite3` 和 `memory-operations.sqlite3`。不能只把 provider 改为 `sqlite` 就无损带回阶段、关系和遗忘规则；SQLite 回退用于旧功能，保留新库备份，恢复 Mem0 后再恢复这套能力。

## 2026-09-09：显式日记授权与三级内容权限

参见 [PRD 隐私权限与数据流增量](PRD.md#15-隐私权限与数据流增量2026-09-09v13)。Memory Review 每页顶部展示当前状态和权限入口；历史、增量、整理、召回分别授权。整篇 `memory: none/local/cloud` 和局部 `riji-memory` 标记同时约束提取与旧检索路径，单条记忆可另设权限。仅本地内容不调用云端提取，当前没有本地生成模型。

保存授权绑定当前来源、版本范围、模型接收方和预算；配置变化后重新授权。暂停停止日记提取与整理；撤回同时停止日记派生记忆的新云端使用。原生聊天与原有受限问答是独立数据流，仍受来源私密标记约束。旧请求和用户独立备份无法由此撤回。
