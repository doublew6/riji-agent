## Earlier append storage and verification history

A single actor serializes storage calls. Before a diary changes, its draft and explicit confirmation transaction are persisted. Replacement writes a unique temporary file, flushes it, atomically renames it and flushes the containing directory. The resulting Markdown is read and verified before a receipt is persisted. Draft and transaction cleanup comes last. No success message appears until this completes. If cleanup fails, retry uses the same receipt and never appends again.

Recovery only completes an already persisted confirmation. The current diary must match the recorded before or after hash; any unknown state stops automatic writing and retains the draft/transaction. Reusing an operation ID with changed payload is rejected, including before transaction persistence when its draft already exists. Editing creates a new candidate ID while retaining the day, effective template and source version; an unchanged retry keeps its original ID. Independently confirmed identical text gets a fresh ID and is saved again. Receipt history is intentionally retained for retry detection in this slice.

Draft typing is queued in order to disk, outside the diary; superseded queued revisions are skipped before their writes. Save and navigation wait for the latest retained version. The UI only reports retained text after its write succeeds; a failed write keeps the latest visible text and reports the failure. A forced termination before a pending draft write reaches disk can only restore the last successfully persisted version. A draft's date is never silently changed at midnight or after travel; use **回到今天** or date navigation explicitly. Navigation preserves drafts for other days in the directory.

The app matches complete ATX Markdown headings outside backtick/tilde fences, HTML comments and frontmatter, including nested section boundaries. It rejects missing or duplicate destination headings, and input that would hide an existing heading or introduce a duplicate existing anchor. Such input stays in the draft. Appending inserts the original user string unchanged, with only the required surrounding line separator, while preserving all preexisting Markdown bytes. Safe template rendering supports only `{{date}}`, `{{title}}`, `{{date:YYYY-MM-DD}}` and `{{date:dddd}}`. Calendar dates and weekdays come from the selected fixed `JournalDay`, including leap days and calendar-year boundaries. Templates → 星期语言 exposes a persisted Chinese default and English option. Substitution is single-pass; tokens in replacement titles and unsupported macro/script expressions remain literal. Template scripts are never executed. Existing diary bodies are never re-templated or overwritten wholesale. Reading renders inline heading styles while keeping the raw heading identity and exact append anchor. A unique Notes heading such as `## 🧠  **Notes**` is the default quick-capture destination; matching normalizes display whitespace only. Multiple equivalent Notes occurrences require explicit selection, and exact duplicate destinations still fail appender validation. Fenced/comment headings are excluded. Reading still presents literal Markdown body text; full list/table/link/local-attachment rendering remains separate work. Imported templates use a separate safe representation that retains unsupported macros visibly and never evaluates them. Only explicit raw-preview confirmation copies a selected file into the library; existing day bodies and old draft templates are preserved. Reopening that template kind or reimporting the same bytes recovers a previously confirmed transaction using its original source checks. Content-identical versions share one list identity, including bytes identical to a bundled template, while the imported raw file remains available. Saved diaries without template provenance use a neutral label instead of claiming the currently selected global template.
